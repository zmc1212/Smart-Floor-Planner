# 小K 四端角色化周报合同（I7.1）

## 1. 数据来源

周报只读取正式业务事实：

- Construction 项目、阶段、房间、成员和权限
- 已发布施工计划版本及节点
- 已发布施工记录和照片
- 当前待办、已确认需求、问题、整改和复核
- 真实发送与回执

不允许模型根据聊天摘要编造项目统计，也不允许把模型日报拼接成周报事实来源。

## 2. 报告合同

每份周报绑定：

| 字段 | 说明 |
| --- | --- |
| `reportId` | 报告 ID；同一周期/接收人/类型确定生成。 |
| `reportType` | 固定 `weekly`。 |
| `enterpriseId` | 企业。 |
| `projectId` | 单项目报告为项目 ID；老板跨项目报告为 `null`。 |
| `recipientId` / `recipientRole` | 接收人和 `owner`/`designer`/`boss`/`worker`。 |
| `periodStart` / `periodEnd` | 上海自然周周期。 |
| `sourceSnapshotVersion` | 事实快照 SHA-256。 |
| `sourceRefs` | 每条结论对应的阶段事件、计划节点、记录、问题、待办、方案来源。 |
| `generatedAt` | 生成时间。 |
| `reportVersion` | 报告版本；数据修订产生新版本，旧版本保留。 |
| `deliveryStatus` | `pending`、`delivered`、`failed`、`muted`、`revoked`。 |

实现：`admin/src/lib/xiaok-v1/weekly-report.ts`。

## 3. 角色内容

### 业主周报

1. 本周施工进展
2. 当前装修阶段
3. 本周完成的事项
4. 目前正在处理的事项
5. 需要业主确认的需求或事项
6. 当前问题和整改情况
7. 下周需要关注的事项
8. 重要资料和现场照片

文风简单清晰，少用专业术语；未记录明确写“未记录不等于未施工”。

### 设计师周报

1. 本周需求变化
2. 待核对图纸和方案
3. 待完善的设计意见
4. 设计相关问题
5. 需要确认的版本
6. 已完成核对
7. 下周设计工作

只包含设计师当前有权访问的项目和事项。

### 公司老板周报

1. 授权范围内项目总览
2. 各项目当前阶段
3. 提前、正常、落后三种计划状态
4. 本周新增问题
5. 待整改问题
6. 已整改待复核
7. 已修正问题
8. 需要老板介入的例外
9. 下周重点事项

支持跨项目汇总。老板身份不自动获得设计审批或工程验收权限。

### 施工人员周报

1. 本周负责项目和施工任务
2. 已提交的现场记录
3. 已处理事项
4. 尚未完成事项
5. 待补充的资料
6. 需要配合的下一步工作

只包含该人员有权访问的任务和项目。

## 4. 一致性与幂等

- 四端可看到不同内容，但阶段、计划颜色、问题状态等共享事实来自同一快照，不得互相矛盾。
- 同一周期、同一接收人、同一报告类型使用同一 `dedupeKey`。
- 报告生成失败可重试；发送失败保留失败状态，不伪装成功。
- 数据修订生成新 `reportVersion`，旧版本和原快照保留。
- 历史周报可重新查看；来源失效或权限撤销时按当前权限隐藏或标记不可用。

## 5. 与现有报告管线

- 复用现有 `construction_reports`、`construction_report_versions`、`construction_report_deliveries`、四角色 binding 和站内投递。
- 新增角色化摘要作为事实投影层，不另建模型运行时，不另建第二套报告事实库。
- 现有日报、阶段提醒和模型正文生成保持兼容。

## 6. I7.2 真实运行

隔离 PostgreSQL 17 中由现有 Worker 生成周报事实、版本、投递和站内消息，验证：

- 四个角色（业主、设计师、老板、施工人员）均有独立报告绑定。
- 老板事实覆盖授权范围内多个项目；业主事实只含自己的项目。
- `weekSchedule` 快照和 `sourceRefs` 随事实保存。
- 同一周期重复 tick 不重复生成报告。
- 退出重新进入通过 `FollowupService.detail` 读取同一 `reportId`、`revision`、`sourceSnapshotVersion`。
- 历史周报通过 `FollowupService.reports` 可读。
- 修订生成 revision 2，revision 1 保留。
- 撤权后历史周报项目范围按当前权限为空，报告不被改写。

正文自然语言整理依赖模型；未配置模型时报告保持 `facts_only`，角色章节、统计和来源仍可用，不写虚假正文。

## 8. 阅读体验与无模型降级（I7.3）

- 小程序周报详情渲染 `weeklyReport.sections`：业主 8 节、设计师 7 节、老板 9 节、施工 6 节；列表卡片增加角色章节预览和摘要。
- `facts_only` 时显示“本份周报按项目事实模板生成，未使用模型整理”，统计与来源不受模型状态影响。
- 详情显示“来源快照 … · 报告版本 …”，历史报告保持原生成快照；修订生成新版本，旧版本仍可读。
- 业主章节只来自已发布对客记录；内部问题、整改备注、复核意见不进入业主周报。
- 未记录明确写“未记录不等于未施工”；不生成完成百分比、提前/落后天数、下周计划或验收结论。

## 7. 测试

`admin/src/lib/xiaok-v1/__tests__/weekly-report-service.test.ts` 覆盖角色投影。`admin/scripts/xiaok-i72-acceptance.ts` 覆盖真实 Worker 生成、四角色投递、重新进入、历史、版本化和撤权遮蔽。
