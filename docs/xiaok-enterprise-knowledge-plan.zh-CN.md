### 1.2 统一开发与自动化验收流程（2026-10-21）

**当前执行规则。** 由用户指定的一个活跃聊天统一持续推进两个计划的开发与自动化验收，1.1节仅划分同一负责人下的代码领域与职责。执行[仓库统一流程](../AGENTS.md#unified-agent-and-knowledge-development-and-automated-acceptance)，取代旧文档中的例行主区冻结、独立测试聊天和跨聊天资源交接要求。历史停止通知和测试记录仍对应各自版本，不作为当前协调门槛或新增通过证据。

- 一个有界功能完成后，由同一聊天执行相关单元/服务及知识与Agent受影响兼容回归、修复失败、完成必需的配置实模/Stable原生检查、更新双语文档并按既有授权本地提交，然后继续下一授权阶段，不再例行确认。内部检查点或跳过的检查不算用户阶段完成。
- 验收绑定实际固定提交或已记录的源码/测试/配置快照，保留前后hash以及分开的夹具、调用与结果。原失败稿、源码漂移批次、unknown和费用事实保持；不混版本、不重放未知运行，不把修复稿算作首稿成功。
- 默认由统一聊天在已授权环境内串行执行。只有明确安排独立/并行工作时，才使用固定版本及隔离工作树、测试数据库、端口、Worker、配置、媒体/夹具和输出；隔离测试核对自己的版本时，开发可继续下一版本。隔离未准备好就串行执行，不把建设CI/容器平台作为当前阶段门槛；此规则不宣称隔离环境或调度器已经实现。
- Stable DevTools原生验收由同一流程中的一个控制者串行运行，保留已验证项目/窗口纪律。既有锁与空闲队列守卫由程序获取并在清理时释放，资源忙时自动等待或续做离线工作；例行争用无需用户批准冻结或跨聊天交接，也不允许抢占其他任务进程。
- 保留真实写入、可见反馈、持久重进、租户/权限/来源撤回和失败恢复检查；未执行/失败与Limited状态如实登记，批准设计及生产授权边界保持。

| 施工工艺/质量检查 | 工序、前置条件、对象/部位、检查方法、数值/单位、例外、来源版本 | 支撑“为什么/怎么做/应核对什么”，不替代现场正式验收 |
| 材料/设备 | 品牌/型号、参数/单位、适用场景、兼容/限制、出处及更新日期 | 专业比较与条件说明，不凭相近型号补参数 |

| 内部培训/协作流程 | 角色/受众、流程边界、内部信息及版本 | 员工按权使用，不能因关联同主题就对客展示 |

- 知识分组/分类服务管理与检索，不作为新的租户或授权真相源。默认沿现有管理权限；扩展编辑/审校/发布角色时分别定义最小权限，并保留admin/super_admin的企业管理继承规则。
- 企业知识描述可复用专业依据；当前项目的进度、照片、客户需求、正式图纸/方案、事项状态继续由获权业务适配器提供，不批量复制成通用知识。企业公共知识可在获权咨询中直接使用，不要求先建线索/工地；项目文件检索继承其原项目/参与者/来源授权。
- 已解决问题可形成待审的经验/FAQ候选，先核对出处、脱敏和使用许可，再由有权人员发布；不自动把私聊、现场判断或一次处理结果变成企业规定。来源撤回对其派生材料的影响必须可追溯。
- 上传、解析、外部OCR/Embedding、引用预览和下载均核验当前企业、操作者与资料受众。客户只读有效customer_public，staff_internal按当前角色/知识访问权限读取；涉及项目/服务资料再叠加原参与者/来源边界，分类标签或LLM生成过滤器不得放宽服务端授权。

### 3.3 入库、结构解析与发布

1. 既有后台`/assistant-knowledge`支持DOCX/可提取文字PDF及有界文字/数字/明确年月日及时刻XLSX导入，沿Ant Design/Admin Pro和共享反馈，保留人工正文/FAQ。文件默认内部受众、未发布/待核对。XLSX最多8张工作表、各限A1:L64，仍受全文件128片/16,000字符/48,000字节与单片512 tokens限制；公式/缓存结果、累计时长/区域短日期、未支持数字格式、隐藏内容、批注及复杂表结构明确失败。date-v1仅转换明确完整年月日和有效整日序列；time-v1支持h:mm/hh:mm整分钟、h:mm:ss/hh:mm:ss及完整日期后接时刻，秒按十进制舍入，保留原值/格式，不推断时区，纯时刻限单日、跨午夜舍入失败；1900序列60等无效日期失败，不把示例日期变成项目安排。扫描/OCR、旧XLS/PPT仍为后续扩展，不作为专业答疑推进前置。
2. 已登记私有原件/hash/许可并校验实际格式。解析沿原knowledge_parse任务，在无继承凭据的本地子进程执行，192MB V8堆/20秒及有界输入输出，ZIP/XML另有路径、解压和实体等资源限制；失败保留原件/任务。不接受任意URL抓取，当前没有外部OCR/解析服务；未来外部适配仍须符合该企业数据授权。
3. DOCX保留标题、正文段落、表格行列/合并跨度、表头及相邻注/脚注；PDF提供实际页码和提取文字，不声称理解表格/图示；有界XLSX保留工作表、稀疏坐标、合并锚点、原表头/单位及同表注/例外，不生成打印页。未支持的SpreadsheetML编码转义文字明确失败。图片、页眉页脚、修订/外链等按实际警告核对；扫描页明确需OCR。后台展示原件、结构/警告和索引文字，review确认警告/排除片段；原文改动须上传有出处的新文件，不能任意改写解析原文或已发布版本。
4. 已实现草稿→解析/核对→索引就绪→有权发布；解析或索引成功均不等于发布。待审/内部材料不能进入普通客户检索。有效期参与检索，未来替换不会提前隐藏有效旧版，替换就绪判断使用数据库时钟；定时切换服务尚未交付。
5. 同一原键/草稿hash复用解析任务/结果，改稿、撤回、取消、操作者撤权及租约变化阻止晚到提交；本地已知失败/取消可显式重试，最多3次。沿原任务、并发/配额和外部Embedding未知结果协议，不另建任务权威或把未知成本填零。

### 3.4 专业检索与上下文组装

1. **先硬授权**：现有企业、参与者/服务范围、有效发布、受众、版本、profile及来源撤回继续在数据库/服务端过滤。当前不开放客户端/模型任意过滤器、tenant或内部草稿范围；后续适配也不得覆盖硬授权。
2. **复用当前问题与实况**：Agent将服务端当前原问题和模型检索词组成一次有界查询，保留明确对象；绑定房屋的知识查询同轮刷新获权材料及施工快照，短追问也能取得实际阶段。不从提问/模型猜房间、材料或城市条件；未知保留为未知，必要时最小澄清。
3. **当前混合检索配置**：professional-hybrid-v5沿用1024维、每路最多30候选、RRF k60、相关度下限0.3和最终最多5片；上下文选择将明确不适用阶段后移、优先覆盖不同文档，保留融合序/选择序。BM25、通用术语库、父子补检和外部重排均未接入，后续按实际问题评测增补，不默认更换向量库。 查询侧现为有界 `renovation-terms-v1`：四组明确术语写法、既有签约意图和完整 C1/C2 代号空格规范化，每题最多8条规则/64个新增词；保留原问题，原词权重3、普通扩展1，原签约意图仍为3。原索引/profile/hash不变，不追加Embedding/LLM调用；同一实际trace保留命中规则/新增词/权重，材料、阶段及授权仍取原服务端事实。通用术语、自动条件与语义冲突仍未完成。 两路各前30条的成员及排名由数据库保留，未入某一路时不补排名或RRF分数，诊断使用同一实际排名。
4. **区分已有上下文与后续补检**：文件块已保留同版本必要章节/表头/脚注，不等于通用父子扩展。未来仅在可验证缺口下补同版本、同授权父段落或有界改写/拆分，限制token、次数、耗时/费用并去重；无依据则明确缺项，不无限搜索或自动建施工事项。
5. **冲突与可选重排**：已登记的互斥主题/口径可能重叠时保留双方并先说明待核实；有效版本/适用关系优先，上传时间/分数不裁定权威。自由文本语义冲突检测尚未交付。重排仍为none，未来接入须证明对本期题有效并保留已验收路径的降级，不据此宣称现有完整重排能力。
6. **已有诊断与生成边界**：本人试问可读实际配置、合法排除计数、获权候选/排名、入选上下文及条件缺项，并在重开时重验来源/epoch。统一检索代码/配置已复用到Agent、后台试问及诊断，草稿范围独立；后台试问仍为保守摘录，C01是生成式解释，结构诊断和运营回归不能代替真实客户Agent语义验收。

### 3.5 证据、综合回答与变更失效

本节的原文/版本/定位/epoch与知识来源重验归知识侧；模型目录、综合生成、引用选择和派生答复失效归Agent侧。以下保留既有接入事实，后续按1.1节分工，不由知识库继续修改Agent实现。

- 当前`source-catalog-v1`由服务端为完整获权原文建立引用目录，模型仅选择citationId，服务端装配原sourceId/逐字quote并重验来源；短/长来源共用协议，原文不裁剪，长来源hint只用于识别。可信文件名称版号与工程数值分开校验，尺寸/金额/计算/正式承诺和撤回仍守原边界。v73/trusted-synthesis-v4、两独立企业同一PDF的首稿/质量/隔离及失败证据见[二期合同](./xiaok-assistant-phase-2.zh-CN.md)。公开DTO、API、数据库及原C01来源组件不变。
- Agent、`KnowledgeRetriever.retrieve(actor, query, epoch)`保守包装器及后台试问/诊断已共用retrieveKnowledge，沿`Evidence`提供sourceRef、版本/hash、原片段、文件定位及专业条件。后续父块等扩展仍须定位到支持结论的原段/表格，保持现有Agent协议。
- 当前synthesis以evidence/advice/uncertainty区分多文档知识和获权业务快照；实际节点、本人资料、明确回传的团队核对及精确正式版本仍由原业务适配器提供，不复制为企业规则。逐字quote只是结构底线，仍须核对结论的语义支持；企业制度/一般建议/现场事实分开，正式费用、决定、落实和验收依真实回执。
- 改版/受众变化/撤回提升并校验knowledge_epoch及精确来源；检索、模型提交、历史投影、媒体和后续投递均重验，同时核对工地业务版本。不能仅删向量而让缓存、旧引用、摘要/组合回答继续外发失效内容。
- 已发布版本不可变，新草稿/解析/索引失败不影响仍有效旧版，新版本核对及索引就绪后原子切换发布指针/epoch。影子profile重建/切换/回滚尚未交付；后续Embedding或维度变化须先建新profile并验证目标集合，1024维不能无迁移混用其他维度，回滚仍守当前授权/有效期。
- KB-4由管理者整理企业共享问题/缺口，复用本人原试问/run和原键恢复，分别记录召回、入选、实际引用及另行核对的专业含义；知识/问题变化收起旧结果，已核对缺口待复验。有界批量支持每批1–20题、并发1–3、本人最近20批、原Worker闭页继续及取消，仍占原企业2,000条回归上限。健康展示真实队列/profile、已知token小计和未知次数/费用，聊天用量仍单独授权；定时计划/规模扩展按需接续，不自动复制私聊或创建施工事项。
