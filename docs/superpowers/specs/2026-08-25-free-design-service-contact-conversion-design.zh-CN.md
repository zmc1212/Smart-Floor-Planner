# 免费设计服务加微信转化设计

## 已批准目标

已匹配设计师的成功态先完成一次联系转化，再成为档案优先的结果页。弹窗关闭后，服务档案是页面唯一主主题、主信息组和绿色强操作；设计师微信降为紧凑辅助动作，添加微信不能阻断服务档案。

## 交互合同

- 新领取结果直接进入 `success`，且已派设计师存在二维码或微信号时，本页面生命周期内自动打开一次共享 `designer-contact-sheet`；用户关闭后不得再次自动弹出。
- 仅有微信号时使用同一弹窗的复制优先状态。没有联系方式时不打开空弹窗，页面展示不可点击的同步中状态。
- 共享弹窗是本路由唯一的二维码和微信号展示位置；结果页不再重复渲染二维码、复制行或大型沟通路径卡。
- 弹窗关闭后，档案 Hero 内承接绿色强主操作「查看服务档案」；设计师卡内只保留紧凑「查看微信」控件再次打开弹窗，不再使用第二个通栏 CTA。既有其他服务需求弱入口继续位于最后。
- 已有服务归属态不自动打断用户，使用唯一绿色「继续查看服务档案」进入原档案；三层原生档案标签也进入同一路由。只有用户点击设计师辅助条内的小型「查看微信」才打开同一联系弹窗，不再渲染第二个通栏描边按钮。

## 视觉结构

- 本文是该路由唯一的组合设计源。成功态采用已批准的 `design-references/free-design-service-archive-first-v1/free-design-service-success-archive-first-v1.png`；已有服务归属态采用用户批准的 C 版 `design-references/free-design-service-existing-redesign-v2/option-c-continuity-archive-drawer.png`。手机号授权态和共享联系弹窗继续保留各自已经批准的状态构图，但不再作为台账中的额外并列来源。
- 共享联系弹窗在小 K 右侧用暖白原生文字气泡说出「比小红书更方便贴心的 / 家装顾问」。弹窗挂载及每次打开时读取原生菜单胶囊底边，并让气泡始终位于该安全边界下方。头衔可见时，关系条只显示「你的专属家装设计顾问」，资历标题组合最终头衔与设计师姓名，并用已许可的金色徽章、指南针和客户爱心图标分别承接头衔、经验与服务人数；二维码舞台尺寸不变。关闭头衔显示时收起资历标题，并把姓名恢复到关系条。
- 手机号授权态移除领取步骤条和所有上门、量房、预约、地址、设计师匹配引导。首屏以「装修问题找微信家装顾问，免费问清楚」承接「三项免费权益」，且只展示「免费效果图 / 出到客户满意为止」「免费家装设计顾问 / 解答你的装修问题」「免费家装现场顾问 / 解答现场问题」，随后呈现手机号隐私说明、主操作「允许微信授权手机号」与弱操作「暂不授权」。
- 手机号授权 Hero 与三条权益是一个按内容固有高度排布的连续阅读组；外层通行证和插画舞台均不得用 flex 扩张或视口派生最小高度吸收高屏剩余空间。小 K 底部必须以设计稿正常分区间距直接衔接第一条权益，权益卡和图标保持设计稿比例；短屏应滚动整个状态，不得压缩该阅读组。
- 在 `390x844` 基准下，本状态按设计稿校准的视觉尺寸为：权益标签 `26rpx`、Hero 主标题 `48rpx`、Hero 副标题 `28rpx`、权益标题 `36rpx`、权益说明 `28rpx`、图标圆底 `124rpx`、可见图标盒 `78–88rpx`、隐私说明 `28rpx`、授权 CTA `32rpx`。这些是本状态的还原目标，不是全局最低字号；窄屏可使用已记录的缩小覆盖，但不得把业务标题与说明降回仅满足最低线的尺寸。
- 已授权后的成功态把三步完成文案压缩为「领取完成 / 授权完成 / 顾问已匹配」；待匹配态及已有服务归属态保持原合同。
- 档案主 Hero 使用「你的服务档案已建立」与「量房、户型、方案与服务进度，都在这里持续更新」。中性的目录行只展示「服务进度 / 户型档案 / 设计方案」；三行与唯一绿色「查看服务档案」均进入现有同一档案路由，不暗示每一栏已完成。
- 批准稿内抱档案夹小 K 映射为独立生成的透明生产素材 `packages/business/assets/referral-service-v1/xiao-k-service-archive-guide.png`；其中非 UI 的窗格、叶片与承托台场景另映射为透明 `packages/business/assets/referral-service-v1/service-archive-scene-v2.png`，置于小 K 后方且不从合成稿切图。页面背景、原生文字、目录行、图标和控件全部使用 WXML/Less 实现。
- 紧凑辅助设计师卡只展示已派姓名、固定客户称谓「家装设计顾问」、真实「已匹配」状态和小型「查看微信」控件。高屏真机截图确认微信原生按钮的自动宽度会挤压角色文字，因此生产态将其固定为 `148rpx` 辅助触点（窄屏 `132rpx`），姓名/角色信息占据剩余宽度；按钮不得扩张为半卡或通栏操作。删除类似「量房预约与方案沟通可通过微信联系」的泛化说明，因为客户可在平台内主动预约量房和查看方案。
- 原说明条仅在存在真实 `professionalProfile` 时改为背书区：按数据展示可见头衔、`experienceLabel` 和 `serviceLabel`，复用已许可的徽章/经验/服务图标。缺少的字段逐项收起；整个资料缺失时背书区完全收起，不虚构头衔、年限或服务人数。
- `390x844` 成功态元素台账：完成步骤圆/文字 `44/24rpx`；档案标题/说明 `48/28rpx`；小 K 与场景舞台 `258×282rpx`；目录行/文案 `94/30rpx`，图标圆底/可见图形 `62/38rpx`；档案 CTA 高度/文案 `100/32rpx`；设计师姓名/角色/状态/联系 `32/24/22/24rpx`，联系按钮宽 `148rpx`；背书文案/图标 `22/34rpx`，第三项服务背书独占下一行并与首列对齐；末级区域/弱入口 `148/26rpx`。末级区域是本页专用的可伸展场景舞台：只有档案与设计师这两个内容固有高度信息组排完后，波形背景才吸收高屏余量。
- 小 K 只在档案 Hero 中承担档案向导角色，不在设计师卡中重复，也不与共享联系弹窗争夺焦点。
- 已有服务归属态把「重复扫码被保护」转译为“从档案柜抽出原档案继续办理”：Hero 使用「已为你接续原有服务 / 人员、进度与服务档案都已保留」，主票据内并列真实「服务归属已保留」、脱敏免费设计服务标识、当前阶段和最近更新时间。三阶段路径仍只由现有线索状态与服务阶段文案派生；文案包含「现场顾问」或「上门」时归入「量房安排」，不把匹配现场顾问错误标为需求确认。
- 票据下半部使用原生定位的「服务进度 / 户型档案 / 设计方案」文字覆盖在三层空白档案签上，三项与唯一绿色「继续查看服务档案」均进入原服务档案。页面不把目录文字、进度或按钮烘焙进图片，也不暗示户型或方案已经完成。
- C 版档案柜和抽取文件的小 K 映射为内置 ImageGen 生成并完成透明通道优化的独立素材 `packages/business/assets/referral-service-v1/xiao-k-continuity-archive-drawer.png`：`720×346` 索引色透明 PNG，`25733` 字节。素材只包含角色、空白档案柜和文件夹；页面文字、状态和控件全部为原生节点。
- 已有服务归属态的设计师辅助条读取项目聚合已有的 `designer` 与公开 `professionalProfile`：姓名、固定「家装设计顾问」、真实匹配/同步状态，以及存在时的头衔、经验、服务人数背书；缺失字段直接收起。微信按钮固定宽 `148rpx`（窄屏 `132rpx`），不能扩张成半卡或通栏操作。
- `390x844` 已有服务归属态元素台账：Hero 标题/说明 `48/28rpx`；归属徽标/脱敏服务标识 `24/22rpx`；当前阶段标签/值/更新时间 `22/36/22rpx`；阶段圆/文字 `46/24rpx`；档案柜舞台高 `318rpx`、原生档案签文字 `24rpx`；主 CTA 高度/文字 `100/32rpx`；设计师姓名/角色/状态/联系 `32/24/22/24rpx`；背书文字/图标 `22/32rpx`；归属说明文字/图标 `22/30rpx`。所有信息组按内容固有高度连续排列，高屏剩余空间只能落在整个内容流之后。

## 边界

- 保持路由、API、领取幂等、客户会话刷新、设计师数据、权限、服务档案导航和其他需求导航不变。
- 小程序无法验证个人微信好友请求是否成功，不保存或宣称「已添加」状态。
- 使用原生 WXML/Less 和既有居中弹窗动效。手机号授权 Hero 的独立透明小 K 三权益素材为 `packages/business/assets/referral-service-v1/xiao-k-three-benefits.png`；成功态 Hero 使用 `xiao-k-service-archive-guide.png`；已有服务归属态使用 `xiao-k-continuity-archive-drawer.png`。页面结构、文字、档案目录、背书数据、隐私说明和操作控件不得烘焙进图片。
