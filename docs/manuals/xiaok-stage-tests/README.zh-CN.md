# 小K Agent 与企业知识库分阶段手测

当前微云企业已有可保留的[测试数据、账号与入口清单](../../xiaok-manual-test-data.zh-CN.md)（2026-10-30）；本次实际ID与状态以该清单为准，以下通用角色和历史基准不覆盖它。

这套手册用于从小程序走完一次真实服务流程，再按两个专项计划逐项检查。第一次请先读本页的准备说明，使用[测试资料](./test-materials.zh-CN.md)，执行[完整流程](./full-flow.zh-CN.md)；之后按下表补测各阶段。每个阶段都写明入口、原话、操作、预期、重进和异常检查。

如果由独立Codex对话执行，使用[自动化测试执行说明](./automation.zh-CN.md)：共用本套场景，按客户端单元、真实服务、Stable原生及当前配置实模分别执行和记录，文末附可直接粘贴的新对话任务。无需把人工操作步骤另复制一套，也不把新增手测设为开发前置门槛。

编写基准为 **2026-10-20 当前工作区代码及二期合同**。`AG-*` 是 Agent 能力工作包，`KB-*` 是知识专项阶段；v68～v89 等是内部技术迭代，不是新增小程序页面，分别归入对应工作包。不能把阶段编号、已有自动化通过记录或模型回答一次成功，当成整个计划已经验收。

## 先确认测试环境

1. 使用开发版、已提供的体验版或已核实的 Stable 微信开发者工具项目；请准备人员记录本次小程序版本、后台版本、服务地址和企业。当前工作区仍有未提交改动，不能只凭 Git 提交号判断手机运行的版本。
2. 所有创建、分享、发布、撤回操作只针对**批准开发或隔离环境中，名称以“合成手测”开头的数据**。本手册没有执行种子、改模型、上传体验版或生产部署。
3. 小程序与后台必须连接同一套服务。后台本地入口使用 [http://localhost:3006/assistant-knowledge](http://localhost:3006/assistant-knowledge)；使用已批准的远程开发服务时，沿用该环境现有入口。手机不能使用电脑的 `localhost` 作为服务地址。
4. 请准备人员确认：企业小K已开放、当前模型及所需能力可用、Embedding/profile已配置、原Worker正在处理任务、相关数据库迁移就绪。记录当前供应商与模型名称，不复制凭据。旧 Qwen/DeepSeek 的测试结果不能替代当前模型的表现。
5. 缺少账号、项目、正式户型或资料时，先按下节在批准测试环境补齐。空列表、无法找到入口或后台尚未部署，记录为“环境未就绪”，不要记录成通过，也不要直接归为模型缺陷。

两专项整体仍为 `Limited`。二期合同中的 v89 为内部技术子阶段 `Implemented`；当前GLM实模请求遇到HTTP 429，未产生首稿或交付，不能视为业务通过。v87/v88的模型参数失败和历史未决调用也仍保留。手测遇到同类限流时记录实际服务反馈，由开发核对原运行，不反复重放未知调用。本手册给出**应有结果**，所有本次手测结果均从“未执行”开始，不继承历史通过率。

## 账号与业务资料

请测试管理员先完成这些准备，再将实际 ID 填入本次记录。不要复用旧验收报告里已停用的账号和企业 ID。

| 代号 | 真实身份与范围 | 用途 |
| --- | --- | --- |
| E-A、E-B | 两个独立合成企业 | 正常流程及跨企业隔离 |
| C-A、C-B | E-A 两个不同客户账号，各有本人服务档案 | 私聊、历史及同企业隔离 |
| C-X | E-B 客户账号 | 跨企业检查 |
| D-A | E-A 有效设计师，具备接待及项目分工 | 真人接管、图纸核对、正式方案 |
| M-A | E-A 项目经理 | 成员、节点、回传、正式解决关闭 |
| W-A、O-A | 同项目工人、只读观察者 | 发进展与操作权限对照 |
| T-A | 有知识管理权限的企业管理员 | 知识录入、索引、发布及运营 |
| P-A | 平台 admin 或 super_admin，明确选中 E-A | 管理继承复验，可与正常流程分开执行 |

至少客户和接待员工使用不同真实账号。一个微信账号切换身份只是在切换其已有权限，不等于换成另一个客户；隔离检查需要真正的另一账号/独立会话环境。可由同一测试人员分设备操作，或由同事配合。

业务准备如下：

- C-A 名下的“合成手测甲屋”，一个唯一活动项目“合成手测甲工地”，开启业主访问；实际阶段为 `utilities`（默认名称“水电”）。登记唯一“书房”和“客厅”，并分配上述成员。
- C-B 名下独立的“合成手测乙屋/乙工地”，默认阶段 `masonry_carpentry`（“泥木”），也有“书房”。后续同题对照分别登录两个客户，避免多房屋歧义影响基础流程。
- 两屋需测试正式户型读取时，准备已完成的主正式 `version: 4` 户型，房间对应关系经核实；无须连接 BLE。客户咨询从对应服务档案上下文进入，不能仅在文本里报一个房屋名称就当作绑定完成。
- 使用[测试资料](./test-materials.zh-CN.md)中的 K-A/K-B 正文、内部资料和文件样本；测试照片/图纸使用无真人、无联系方式、能区别 V1/V2 的 JPEG/PNG。
- 创建第二次咨询供“只回原咨询”检查，保留第一次咨询的入口。另一项目、内部资料和对照账号只在负例中使用。

## 小程序与后台入口

| 入口 | 在界面上如何进入 | 实际路由或后台页 |
| --- | --- | --- |
| 客户咨询 C01 | “我的 → 当前身份”选个人用户，回“首页”，在对应服务上下文点击“和小K聊一聊” | `packages/assistant/chat/chat`；有关联时携带 `leadId` |
| 咨询历史 | 客户聊天底部“查看历史”，选择原咨询；已结束对话可“开启新对话” | 同一聊天页，无独立的客户记忆管理页 |
| 员工接待 S01 | 切设计师或企业管理员身份，首页角色工作台点击“小K咨询接管” | `packages/assistant/handoff/handoff?staff=1` |
| 工地协作 S04 | 设计师/施工人员/企业管理员：“我的 → 云工地 → 选择工地 → 进入工地小K对话” | `packages/construction/projects/projects` → `packages/construction/chat/chat?projectId=…` |
| 企业知识 | 后台选 E-A，打开“小 K 知识库 → 企业知识” | `/assistant-knowledge` |
| 后台试问 | 同页“管理员试问” | 本人私有试问；不等同于绑定项目的客户 Agent |
| 知识运营 | 同页“问题集与健康” | 问题、缺口、单题/批量回归及健康，无小程序运营页 |

入口受身份和企业能力控制。未出现相应入口时，先核对当前身份、部署版本及授权，不自行寻找一个新页面代替。

## 记录方法与完成口径

每个用例单独选择：**未执行 / 通过 / 失败 / 环境未就绪 / 当前未实现 / 需开发配合核实**。能打开页面只完成了入口检查。一次有效流程还需检查真实反馈、退出重进、正确账号可见，以及不该有权限的账号无法继续读取。

复制以下表格到你本次的测试记录中；不需要先编辑项目计划。截图可选，记录实际原话和结果更有利于定位。

| 日期/人员 | 环境/小程序及后台版本 | 企业/账号/模型 | 用例 ID | 咨询/项目/事项/来源版本 ID | 实际结果与状态 | 问题原话/反馈/发生时间 |
| --- | --- | --- | --- | --- | --- | --- |
| 待填 | 待填 | 待填 | 待填 | 待填 | 未执行 | 待填 |

失败后保留第一次原稿、发送时间、可见状态及原咨询；不要不断重发“保存/发布/同意”来冲出一次成功。出现“确认发送结果”“核对同一次操作”等入口时，先用它核对。修复复测另记一行，不覆盖原失败；模型调用结果未知时由开发核对原运行，不手动重放未知调用。

手测能发现语义与流程问题，但看不到服务端压缩次数、幂等事务、租约竞争、全量撤权或供应商账单。各阶段已列出需要开发配合的证据；手测通过不能替代这些检查，也不构成发布批准。本次按用户主动要求提供手测，不把手测、截图或真机检查增加为后续开发的等待门槛。

## 范围与维护依据

业务阶段对应关系：P2S/P2M.1～.3 覆盖开聊、记忆和专业问答；P2B 覆盖真人接待；P3B/P4A 覆盖实际节点、共享资料及事项；P5 覆盖精确方案决定和落实关闭。P2M.4语音仍 `Placeholder`，P6完整经营服务、通用跨天任务、OCR、复杂表格和大规模容量按专项剩余范围记录，不能要求当前页面完成。

维护时对照[Agent计划](../../xiaok-agent-engineering-plan.zh-CN.md)、[知识计划](../../xiaok-enterprise-knowledge-plan.zh-CN.md)、[二期合同](../../xiaok-assistant-phase-2.zh-CN.md)、[小程序清单](../../miniprogram-system-modules.zh-CN.md)和[后台清单](../../admin-system-modules.zh-CN.md)。两专项计划的中英文版均链接本套中文手册。本次仅新增测试文档及文档入口，没有改变产品路由、API、数据模型、权限、界面或功能状态。
