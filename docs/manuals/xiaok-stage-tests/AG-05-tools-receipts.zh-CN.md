# AG-05 工具执行与真实回执手测

当前 `Limited`，对应 P2M→P5、QA-08、XK-05/08。检查“说已办成”和真实业务结果一致，提交未知时核对原操作。先完成[共用准备](./README.zh-CN.md)，准备独立咨询、共享资料 G、现场记录 R 和事项 I；正式操作格式见[完整流程](./full-flow.zh-CN.md)。

## 正常工具与服务回读

| 用例 | 身份/入口及操作 | 预期 |
| --- | --- | --- |
| AG05-01 需求保存 | C-A原咨询明确更正书桌/预算，等回执后回读，退出重进 | 只有实际写入才能说已保存；同轮合法多字段一起成功或如实失败，不虚报部分结果 |
| AG05-02 只读查询 | C-A问“我家书房实际节点和现场资料是什么？请按现有来源说明” | 使用当前绑定房屋，不要求用户自己填写工具ID；缺资料不能编造，参数失败不能说已查到 |
| AG05-03 来源核对 | D-A工地聊天 `查看书房资料`、`核对事项I图纸G` | 真实关联当前资料；查询/核对不形成客户批准 |
| AG05-04 真实发布 | 经理按完整流程发布一条人工核对的现场记录；C-A仅在明确向业主开放或正式结果授权后读取 | 可见范围与发布选择一致，草稿不能冒充已发布 |
| AG05-05 精确决定 | 客户查看方案V2原件，点明确同意，重进再查询 | 同意绑定同一版本；“好”“可以”或同意旧版不能批准新版 |

## 可直接手测的失败与权限

1. **AG05-06，D-A/M-A工地聊天**：用真实 I 按发布方案命令发送，但故意省略“费用变化”一行。应明确拒绝格式不全，不生成一个默认费用为0的新方案；修正后以新的明确操作提交。
2. **AG05-07，W-A工地聊天**：附测试原件尝试发布正式方案；**O-A**尝试写现场消息/核对。应按角色拒绝或无可用动作；不能靠换句式成功。只读观察者不应得到编辑/发布权。
3. **AG05-08，M-A**：对尚未落实的独立事项直接发多行“解决事项I”，或在未解决时“关闭事项I”。应因状态/依据不足拒绝，不能只生成成功话术。
4. **AG05-09，两个有编辑权的会话**：都打开同一草稿，一方先保存，另一方再保存旧版。应提示版本冲突并保留待提交输入；读取最新版后再核对，旧操作不能覆盖新版本。

负例只使用独立合成事项；不要在主流程已经关闭的事项上做“回复/取消”来验证普通待办。

## 断网与未知结果

**AG05-10** 在发送普通文字或执行一次测试发布前后短暂断网，恢复网络后观察。断网时机不同，可能得到“明确失败”或“结果待确认”，两者应分别记录，不能强求每次都复现未知。

- 明确未提交：输入保留，可使用已有重试入口。
- 结果待确认：先点“确认发送结果 / 核对同一次操作 / 核对同次决定”等当前入口；退出重进后仍核对原操作，不重新创建方案或重复点同意。
- 页面恢复后只有一份实际写入、一份对应版本/决定，回执与当前权限一致。需要开发核对操作键、业务记录和版本计数；一条可见气泡只能作为支持证据。

不要仅为手测制造供应商未知调用后反复“重新回答”。模型/工具超时、丢回执、无效工具参数的有限修正、真正未知执行结果不重发，需要开发在批准隔离环境做受控注入并查原 run/operationId。

## 当前限制与记录

v87/v88真实模型曾重复发送错误类型的房屋ID；v89会话身份绑定已完成内部技术子阶段，但当前GLM实模请求遇到HTTP 429，未读取资料或交付回答，原运行结果待核对。AG05-02应记录当前模型实际行为，不把内部修复或确定性单元通过当客户交付。每条登记原话、动作时间、可见反馈和重进状态；任何“成功但无业务记录”“失败却重复写入”都按失败记录。
