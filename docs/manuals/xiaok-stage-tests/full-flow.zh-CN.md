# 小K从知识入库到事项关闭的完整手测

按顺序执行，使用[总说明](./README.zh-CN.md)中的账号和[合成资料](./test-materials.zh-CN.md)。这是当前已有限定实现的客户服务主流程，覆盖 P2S/P2M.1～.3、P2B、P3B/P4A 和 P5；不代表完整 PPT、语音、设备或经营服务已交付。**本页所有结果尚未执行。**

每步记下实际账号、咨询/项目/记录及版本编号。命令里的 `R/I/G/V/F` 是变量，发送前换成回执中的纯数字。工地命令发在**工地小K对话**，客户问题及共享命令发在**客户原咨询**，不要混用。

## 01 让客户查到一份实际发布的知识

1. **T-A，后台**：选 E-A，打开“小 K 知识库 → 企业知识”，按资料页新建 K-A、K-B，保存、索引到就绪、明确发布。记下文档与发布版本。暂不发布冲突和注入样本。
2. **C-A，小程序**：个人用户身份，在甲屋服务上下文点击“和小K聊一聊”。核对顶部企业，保留这次咨询为“原咨询”。
3. 发送“书房长期用电脑，书桌靠窗时要先考虑什么？请按现有资料解释。”等回答完成；点回答下方来源片，查看标题、版本和引文。
4. 再发“如果还没有现场尺寸，能直接确定插座位置吗？”

**预期**：有依据时能解释采光/使用习惯、点位先核对等条件，引用支持所说内容；缺量测不能编造尺寸或说已批准。不要求先填电话、先建线索或确认摘要。退出小程序再从“查看历史”进入，原问题与可用来源仍在。若模型未完成回答，记录失败/实际错误，不能因后台索引成功就通过这一步。

## 02 保存需求并作一次明确更正

**C-A，在同一原咨询**，逐条发送：

```text
请记下：书房书桌靠窗，书房需要收纳。
请记下：全屋预算20万元，客厅保留阅读角。
更正：书房书桌改为靠内墙；全屋预算改为18万元。其他需求保持原样。
只回顾这次聊天里的原话：书房、客厅和预算现在分别是什么？不要查工地或企业资料。
```

**预期**：当前书桌为靠内墙、预算18万元，收纳与客厅阅读角仍保留；能区分旧说法与更正。只有实际保存才能报已记下，不把更正变成方案批准。退出重进后再问一次，结果保持。发送“假设书桌仍靠窗，有什么取舍？先不要修改需求”，讨论后当前记忆不应被改回靠窗。

## 03 明确共享给项目成员

1. **C-A**，发送 `共享书房需求：书桌靠内墙，保留收纳；请核对插座位置与现场尺寸。`，记下需求共享编号 N。
2. 点击输入框旁图片按钮，发送“合成点位图V1”；紧接着发送 `共享书房点位图：合成点位图V1，仅供核对关联，现场尺寸未核对。`，记下图纸共享编号 G。
3. **D-A**，“我的 → 云工地 → 甲工地 → 进入工地小K对话”，发送 `查看书房资料`。

**预期**：客户有持久化的共享回执，员工能读到这两份明确共享的资料及图纸原件，显示编号/来源；不会因此看到全部私聊。私图上传提示当前不能自动识图不算失败，但不能冒称已识读。共享说明里的“V1”不是正式方案版本，更不是客户批准。双方重进后来源一致。

## 04 真人接手同一咨询

1. **C-A**，点“找设计师”；等待时再发“补充：阅读角希望保留原家具”。
2. **D-A**，切设计师身份，首页点“小K咨询接管 → 待接待”，找到本次请求。接管前应只见接待请求信息；点“接待客户”。
3. 打开“对话”，确认原话及等待时补充都在，回复“我已看到本次需求，现场点位仍需核对”。在“需求/资料”页签查看整理、原话与图片；需要修正时用“修正整理结果”，不要把内部修正当客户批准。
4. **C-A**，确认收到真人回复，点“结束接续，回到小K”，再问“我们刚才确认了哪些意向，哪些还待核对？”

**预期**：等待/真人状态可见且重进保留，这段时间小K暂停自动回复；结束后可继续 AI。D-A 不再有本次私聊的接待访问。若并发生成中转人，迟到的 AI 回答不能打断真人。结束接待不撤销第03步的独立项目共享。

## 05 在工地形成同一条待处理事项

1. **W-A 或 M-A，工地聊天**：发送 `合成手测：书房点位尚未核对现场尺寸，本次仅登记待沟通事项，请设计师核对书桌位置与插座。`。
2. 原话保存后，在草稿上点“修改内容”，选“书房”，核对标题和“待沟通”；不能把未核对内容写成已完成。由有权人员“核对并发布”，基础流程可只向项目成员发布。
3. 发送 `查看书房记录`，从查询回复找到这条记录的编号 R。再发 `跟进记录R：请设计师核对书房点位与客户当前需求`，记下事项编号 I。
4. **D-A** 发送 `接手事项I`，再发 `核对事项I图纸G`，然后 `回复事项I：已核对关联到本次点位图，现场尺寸仍须复核，先不作正式批准。`。
5. **M-A** 发送 `回传事项I：设计师已接手并核对本次资料关联，现场尺寸仍待复核，尚未形成正式批准。`。
6. **C-A** 回原咨询，等站内回传，再问“书房这件事由谁处理，现在在等什么？能算已经解决了吗？”

**预期**：始终是同一 I，负责人正确，处理回复仍是待核对；原咨询只收到管理者明确选择的节选，不收到内部完整聊天/照片。普通“收到”、回复或资料核对不自动解决事项。退出双方页面重进再查询，负责人和状态保持；第二咨询不能代收这条结果。

需要额外检查取消、恢复、转交及跨天继续，见 [AG-03](./AG-03-topics-tasks.zh-CN.md)，先用独立事项测试，避免改变这条主流程来源。

## 06 发布精确方案并让客户决定

**D-A 或 M-A，在工地聊天**，附一张本次新上传的测试图纸，原输入框逐行发送，实际发送时把 `I` 替换为事项数字 ID：

```text
发布方案事项I
标题：合成书房点位方案
差异：本版按靠内墙的书桌意向调整示意点位，现场条件另行核对
费用变化：+500.00元
工期变化：+2天
```

这些费用/天数是人员明确填写的合成变化，不是模型估价。记下返回的正式方案编号 V 和版本号。

1. **C-A**，回原咨询查看“这次方案，请你决定”卡，核对房间、版本、差异和两项影响。
2. 点“查看完整图纸与差异”，等原件显示后，先选“稍后决定”；退出重进，状态仍为稍后。
3. 点“希望调整一下”，填“请调整测试图示说明，保留收纳”。普通聊天发“可以”不能代替按钮决定。
4. **D-A/M-A**，附像素可区分的 V2 图，用同格式发布新方案，差异写清本次修改；若无额外变化，明确填写 `费用变化：0元`、`工期变化：0天`。记下新编号 V2。
5. **C-A**，查看新版本完整原件与差异，再点明确同意。旧版决定不能自动批准新版。后续落实使用 **V2 的实际 ID**。

**预期**：每版图纸、影响和客户决定可回读；同意只作用于该精确版本。工地查询能读到“已同意这一版”，事项仍未自动落实/解决/关闭。权限和来源冲突时应拒绝；若回包不确定，按“核对同次决定”处理，不重新创建版本。

## 07 落实、正式解决、关闭分别操作

1. **W-A/M-A** 在工地聊天上传独立的“合成现场完成记录”照片，发送“合成手测：书房本次调整已按当前获同意方案完成，待人工核对记录”。
2. 有权人员“修改内容”，选同一书房；核对“本次完成”为明确完成内容，清空“尚未完成/待沟通”，保存后明确发布。这里是在确认合成记录，不确认真实工程。发送 `查看书房记录` 取得该记录编号 F。
3. **当前负责人 D-A 或 M-A** 发 `落实事项I方案V2记录F：已核对本次合成完成记录及照片与获同意方案的关联。`。这里的 V2 要替换为实际数字方案 ID，不发送字母 V2。
4. **M-A** 分别发送下面两条多行命令，每次等回执后再发下一条：

```text
解决事项I
结论：已核对本次合成落实依据
回传：本次合成事项已正式解决，尚未关闭，不代表工程验收或付款
回传原件：是
```

```text
关闭事项I
结论：本次合成事项处理完成，登记关闭
回传：本次合成事项已关闭，工程验收与付款不在本次决定范围
回传原件：是
```

5. **C-A** 回原咨询，看最新有效结果及明确开放的照片，预览后退出重进。发“这条事项现在什么状态？是否意味着整个工程已验收或已付款？”

**预期**：先 implemented，再 resolved，再 closed；缺获同意方案、缺同房间已发布完成记录/照片或跳过解决时应拒绝。客户只见回传节选及明确开放的原件，不能打开内部项目会话。最新回答应区分事项关闭、工程验收和付款。后一状态使旧状态回执失效时，以当前有效结果为准，不要求旧 resolved 气泡永久可用。

## 08 撤回来源后检查历史与后续回答

此步骤放最后，会使依赖该来源的正式方案、事项结果或派生回答失效。

1. **C-A** 在原咨询发 `撤回共享资料G`，使用第03步真实图纸共享 ID。
2. **D-A/M-A** 在工地聊天重新“查看书房资料”，再查事项；退出重进，旧共享图纸不能继续读取，旧处理依据不能沿用。
3. **C-A** 重新查看依赖该资料的旧方案/回答/照片入口，再问“刚才撤回后，那版方案和关闭结果还能继续作为有效依据吗？”
4. **T-A** 在后台撤回本轮独立测试的 K-A，C-A 打开引用 K-A 的旧来源片并重新提问。

**预期**：相关旧内容收起、提示不可用或按当前来源重新解释，不能用缓存/旧成功回执复活撤回依据；独立的客户当前需求不因此被改回旧值。其他合法独立授权仍按各自权限处理，不要求无关内容全部删除。恢复测试要用新的有效资料/核对和决定，不能只重新加入成员或重发旧回执。
