## 当前交付的验收任务与边界

默认同一负责人实施、修复并验收一个当前业务交付；不新建例行测试聊天。只有用户明确要求独立评测才使用独立测试职责，且不得并发修改共享实现。

1. 开始前列出交付ID、用户动作、代码缺口和固定完成条件，选择对应FLOW/AUTO/AG/KB子集及必要安全负例。已完成项先复用证据，不先启动全流程。
2. 编辑过程中运行受影响快速检查；集成后执行真实服务及受影响兼容，最后完成必要Stable原生。当前新增或实质改变的核心语义题按配置模型至少两次；确定性业务改动不追加无关实模。
3. 每次重跑说明改动/原失败/未解风险，核对该检查实际依赖、驱动与配置。稳定未改的检查可复用；文档、新聊天和版本号变化不是全量重测理由。依赖漂移不能混用成绩。
4. 同类业务预期连续两轮修复仍失败，按根规则先做共同原因诊断，不进行第三轮措辞补丁和全套重测；跨聊天继续计数。安全缺陷仍阻塞所有受影响路径；无依赖的下一已授权交付可串行推进，原失败保持。
5. 缺数据就在批准开发/隔离环境建立标记合成夹具，真实操作/写入/回读；不能用伪造页面数据或网络成功完成断言。unknown不重放，费用不填0。
6. 实现、必要验收、双语文档和相关本地提交完成即更新当前交付并继续下一项，不等待用户手测/截图。内部补丁/拒绝成功不计正常业务交付；新设计、付费模型和生产操作仍守授权边界。

## 先建立可核对的测试基线

1. 阅读根`AGENTS.md`、`admin/AGENTS.md`、两个专项计划、当前二期合同/交接及相关中英文模块清单，核对最新状态，不把本文写作时的版本当作永久现状。使用context-mode精简日志，不输出凭据。
2. 检查当前Git状态、附着工作树和正在进行的开发。记录HEAD、未提交改动和本轮实际source/test/config标识；每个验收窗口前后核对相关hash。源码漂移的结果保留为失效窗口，在稳定版本重新执行，不能与另一窗口拼成通过率。
3. 如要隔离，复用合适的托管工作树，或按仓库规则创建`codex/`工作树；工作树不包含当前未提交内容。不得默默从缺失本地改动的远程分支开始，也不能为测试擅自提交、丢弃或复制混杂改动。无法取得明确基线时，先做独立只读核查并说明问题，暂不宣称当前开发成果已验收。
4. 核对后台/小程序是否使用同一服务，读取当前模型与能力，不记录密钥。涉及SSH或远程服务时先读`docs/remote-development.md`及其中文镜像，遵守既有访问/部署边界。
5. 准备E-A/E-B、客户/设计师/经理/工人/观察者、甲乙房屋项目、正式v4户型及知识样本，记下新ID。不要复用已停用历史账号，也不重放旧unknown任务。
6. 数据库写入验收沿用`admin/scripts/assistant-acceptance-safety.mjs`的共享锁和空闲队列守卫。服务测试、实模和原生驱动按依赖顺序运行，不让独立对话争抢同一隔离库、fixture、Worker队列或DevTools控制器。

## 测试结果按四类分开

| 类别 | 执行内容 | 能证明什么 |
| --- | --- | --- |
| 客户端单元 | Node运行`miniprogram/test/assistant-*.test.js`等相关测试 | 控制器/客户端逻辑；不能计为Stable原生操作 |
| 服务与数据 | 真实HTTP/业务服务、数据库、Worker、版本/权限、幂等及受控故障 | 真实业务结果与恢复；不能独自证明界面可用或模型语义正确 |
| Stable原生自动化 | 真实页面输入、点击、上传链路、导航、引用展开、重进和异常反馈 | 本轮原生客户端服务链；基础连接/截图不等于所有业务通过 |
| 当前配置实模 | 实际模型请求、首次回答、引用/事实/建议/未知核对及实际用量 | 本轮指定模型在固定场景的表现；模拟provider不算实模，后台摘录不替代客户Agent |

一条用例可能同时需要后三类证据；同一检查不能相加制造更多“通过项”。截图、页面气泡、数据库写入和模型首稿分别核对，不能以其中一项代替全部结果。

## Stable微信开发者工具执行规则

以根`AGENTS.md`的完整窗口纪律为准。当前已验证组合为Stable `2.02.2608080`、`miniprogram-automator@0.13.0`、基础库`3.17.2`，逻辑视口`390×844`。不退回已知冻结的Nightly。

- 核实唯一项目的绝对路径等于当前批准测试基线的`miniprogram/`路径；复用已有且有有效automator端点的项目窗口。不要用IDE HTTP服务端口当automator端口，不创建临时项目副本或重复窗口。
- 普通项目窗口没有automator端点时，仅按已授权流程关闭**核实过的该项目窗口**，确认关闭后用同路径`cli auto`替换，优先空闲的9420；不退出整个DevTools。路径不明、同项目多窗口或可能影响其他项目时，按根规则询问用户，继续其他独立检查。
- 每次控制/打开/重开项目后，先新编译，再连接并核对`systemInfo`、非空`page.data()`、有效元素查询、真实输入/点击和运行页面栈。首次RPC超时需显式重新编译后重连重试，不能立刻认定业务不可用。
- Stable项目窗口保持在副屏，打开、重开或自动化操作前先确认位置，不遮挡主屏、不反复抢焦点；无法确认时暂停窗口交互并继续独立后台检查。截图前确认栈顶目标路由和已渲染状态，不能用首页图证明聊天页通过。记录逻辑视口与实际PNG尺寸。
- 文字、方案决定和恢复动作走实际页面元素及真实服务；不得通过`setData`、伪造网络成功或替换业务返回完成断言。用合成身份进入会话可以作为fixture，但必须说明身份注入范围，后续真实权限校验仍须执行。
- 自动化中相册选择、原生确认框等若使用SDK注入合成选择，应记录注入边界，不称作真实手机相册/相机/微信授权通过。模拟器限制、真机/BLE/真实微信授权未测单独列出，不交给用户做必需手测。

## 模型失败与证据

每批固定必要/禁止来源、条件和应有业务状态；关键正向题未交付就记录未交付。HTTP 429、超时或供应商未知结果，分别记录请求实际失败及后续未执行断言，不自动换供应商，不把未知费用填0，不重放原unknown任务。当前配置可受理时，可按原安全协议建立新的明确运行；仍保持原始失败及用量。

输出放本轮独立`tmp/xiaok-auto-日期-唯一后缀/`，至少保存：

- 实际source/test/config标识、首尾hash、环境、fixture与清理结果；不保存明文凭据或无关客户资料。
- 每用例预期、实际输入、原咨询/项目/issue/版本/run标识、真实业务回读与状态。
- 栈顶路由、SDK/基础库、逻辑视口/截图尺寸及相关原生截图；注入选择器/确认框等边界。
- 首稿、修复后稿与失败分别保留，模拟/实模/原生检查分别计数。不要把修复后成功冒充首稿正确，不合并不同源码/模型的成功率。
- 未执行、当前未实现、环境或外部服务阻塞分别列原因；清理只处理本轮夹具，保留未知调用供原协议核实。

在聊天中直接交付通过/失败/未执行摘要、问题原话与复现步骤、原生是否执行、真实模型及其结果、仍需开发处理的缺口。适用的当前证据精简更新到既有阶段合同及中英文清单，不给两个计划追加长篇流水日志。手测仍是用户可选补充；不要求用户截图或补手测来代替本轮自动化。

## “继续”的执行模板

```text
继续统一实施两个计划。先核对Agent计划第1节的当前交付、知识计划的依赖记录和最新交接；已完成就推进指定下一项，不从最后一条失败日志或历史全套测试重新开始。

说明本次用户动作、实际代码缺口、必要完成条件和下一项，然后完成实现、受影响自动检查、必要实模/Stable原生、双语文档与相关本地提交。已有有效证据直接复用，重复测试必须说明具体原因。保留原题、正常业务成功、权限/来源撤回、幂等/回执和失败恢复；不能靠放宽守卫或删除失败收口。

同类失败沿原计数执行共同原因诊断；没有新机制依据就保留阻塞并转入有证据表明无依赖的下一业务，不继续换措辞/正则试到通过。汇报新增可用功能、入口、证据、限制与下一项，测试数只作辅助。沿同一负责人和批准环境，不新建例行测试聊天、不抢占资源、不换付费模型、不push或部署。
```

本模板不发消息、不启动任务或自动化。明确要求独立/完整评测时才扩大范围；历史证据保持自己的版本与未覆盖限制。
