# AG-01 上下文与历史回读手测

当前 `Limited`，对应 P2M.1～.3、QA-05/06、XK-01/08。检查长聊之后仍能回读原话、保留更正和否定；小程序没有“压缩历史”按钮。先完成[共用准备](./README.zh-CN.md)，使用 C-A 的一条全新咨询，记下咨询编号。

## 小程序步骤

| 用例 | 操作与可直接发送的原话 | 应看到的结果 |
| --- | --- | --- |
| AG01-01 早期约束 | 同一咨询依次发“请记下：书房书桌靠窗，保留收纳”“客厅不要投影设备”“先不确定装修日期，不要替我定日期” | 原话保存；不把否定变成需要、不编造日期 |
| AG01-02 长聊 | 继续发至少35条彼此独立的正常客户消息，每条等回答结束。可围绕采光、收纳、配色提问并编号“手测追问01…”；不要用同一条刷屏，也不要混入新保存要求 | 能持续回答，无原话丢失；消息数只是准备，不证明已发生压缩 |
| AG01-03 更正后回读 | 发“更正：书房书桌改为靠内墙；收纳和客厅不装投影保持不变”，再发“只回顾这次咨询的聊天原话：书桌、收纳、投影、装修日期分别怎么说的？不要查企业资料和工地” | 当前靠内墙、保留收纳、不装投影、日期未定；不把靠窗旧值恢复成当前要求 |
| AG01-04 更早原话 | 继续正常问答到早期消息超出最近60条客户原话范围，再问“最开始我对书房和客厅怎么说，后来改了哪一项？只回顾本咨询原话” | 有权原话仍可回读，旧/新说法区分清楚；找不到时如实说明，不编造全文 |
| AG01-05 历史与重进 | 点“查看更早的消息”核对最初原话；退出小程序，再从首页小K的“查看历史”进入原咨询，复问当前要求 | 原文完整，当前更正及否定保持；历史入口不是自动合并所有咨询 |
| AG01-06 新咨询隔离 | 开一条新咨询，问“我刚才那间房的书桌怎么定的？” | 不把另一咨询的私有原话直接当成本咨询已知事实；对象不清时先澄清 |

长消息补测：粘贴接近页面实际字数上限的无敏感说明，发送前检查结尾是否完整。当前客户端最高4,000字，后台可下调。界面限制只能证明客户端边界，不能证明服务端超限拒绝或模型预算已通过。

## 失败与恢复

在普通文字发送时短暂断网，再恢复；先用“确认发送结果/核对结果”或已有重试入口，不反复新发同一要求。退出重进后应只有一次已接收的客户消息，待确认内容不应被偷偷丢弃。模型未生成成功时记录实际反馈，不能把“重新回答”后的成功覆盖第一次失败。

## 需要开发配合核实

- 使用已批准测试环境，核对本轮实际配置阈值与 run/step，确实发生至少2次压缩/裁减及阈值前后原文保留；35条或60条消息本身不能证明这点。
- 单条必要上下文超预算、工具大结果、压缩失败、Worker恢复与来源撤回需要服务侧检查。当前是有界原话召回/抽取摘记，不是自由改写摘要或归档规模语义搜索。
- 普通手测若未触发相应阈值，记录“已完成长聊行为，压缩证据需核实”，不能标 AG-01 全部通过。
