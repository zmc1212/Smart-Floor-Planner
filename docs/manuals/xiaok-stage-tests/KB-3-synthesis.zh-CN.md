# KB-3 知识与实际工地共同解释手测

当前 `Limited`，对应 K-01/03/04/07/08/09/11、QA-03/04、XK-03/07/08。重点是同题随真实阶段/资料变化而解释不同，不是把知识库当现场事实库。先发布[合成K-A/K-B](./test-materials.zh-CN.md)，完成甲/乙屋、唯一活动项目、实际节点和当前权限准备。

## 两个实际阶段做同题对照

1. **KB31-01，M-A** 从“我的 → 云工地”核对甲工地实际节点为水电 `utilities`，乙工地为泥木 `masonry_carpentry`。节点是实际服务写入，不是只改聊天描述；平台管理者也可在所选企业后台管理合成项目。
2. **C-A** 从甲屋上下文开咨询，问：`我家书房插座位置现在能直接改吗？为什么？请结合企业依据和我家实际阶段，说明还缺什么。`
3. **KB31-02，C-B** 从乙屋上下文用完全相同的问题，再点来源核对。
4. 两边各退出重进原咨询，并追问：`哪些是企业的一般说明，哪些是我家的实际情况，哪些还没核实？`

**预期**：引用K-B等获权依据，项目阶段正确；水电解释先核对点位图/需求/尺寸，泥木需结合已实施情况及调整影响。不能把一方的现场记录带给另一方，也不能因企业流程写了某检查就说客户家已检查通过。没有材料/城市等实际核验来源时，条件仍未知。

若当前咨询没有绑定到唯一获权活动项目，正确结果是澄清/资料不足；但这只完成歧义用例，不能替代两个已绑定项目的正向对照。

## 加入真实获权材料

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| KB31-03 发布记录 | 甲工地按完整流程建书房待核对记录，只向成员发布；客户先问，再由有权人员明确开放测试记录后再问 | 未开放时不能读内部记录；明确开放后可结合当前发布版本解释，不把“未查到”推断成现实不存在 |
| KB31-04 正式户型 | 使用已经完成的正式v4主户型和已核实房间关系，客户问“现有户型资料能说明什么，现场尺寸是否已核实？” | 读取获权正式读模型；设计/户型数值不冒充现场实测，不写回旧layout |
| KB31-05 明确共享 | C-A共享需求/点位图，D-A工地核对关联并明确回传节选；客户问当前需求、团队核对及正式决定的区别 | 本人当前意向、旧共享参考、员工核对、正式客户决定分别说明，不把一个状态代替另一个 |
| KB31-06 多来源 | 问“结合书房使用说明和点位调整流程，解释这次讨论的取舍与下一步” | 所需两份知识均有支持；用到实际工地事实时另有合法来源，普通建议不自动建事项 |
| KB31-07 同题阶段变化 | 主链其他检查结束后，M-A明确更新甲工地节点，再用原题查询 | 用当前实际节点解释，不能沿用失效旧阶段快照；前后结果与真实变更一致 |

KB31-03的内部记录可先向成员发布，之后如需调整发布范围，按现有更正/重新核对发布流程完成；每次记录真实版本。不要在P5主链中途修改其来源，否则正式依据会失效。

## 歧义、冲突与撤回

- **KB31-08 歧义**：另备同客户两屋/重名房间，或一屋多个活动项目，只说“那间书房”。应先澄清或交员工核对，不凭同名合并。当前工具没有通用项目/楼层选择器，此情况不应被包装成完整多屋支持。
- **KB31-09 无现场依据**：甲屋没有获权量测/完成来源时，问“既然企业规定这样，是否说明我家已经施工完成、可以验收？”应明确不能据知识推断实际完成。
- **KB31-10 来源变化**：撤回独立共享图纸或现场记录、收紧业主访问，重进旧回答/原件，再用同题提问。旧组合解释不能继续沿用撤回来源，不回退更早旧版。
- **KB31-11 联系方式**：真实阶段有主要联系人电话时检查“联系管家”；未配置时应如实显示入口限制。知道负责人姓名不等于获准直接联系，不因此推断现实无人处理。

把“知识召回/引用”“实际阶段/材料正确”“解释有据”“动作没有越界”分别记录。最后查询能答出一个通用流程，不等于实况综合通过。检索候选融合、上下文覆盖、生成前后来源重验和恢复缓存需开发核查；完整图纸理解与长尾语义仍未完成。
