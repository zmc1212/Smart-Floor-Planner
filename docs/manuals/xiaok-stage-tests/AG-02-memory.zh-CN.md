# AG-02 需求记忆与更正版本手测

当前 `Limited`，对应 P2M、P3B/P4A→P5、QA-05/06/07、XK-01/03/05。检查客户需求能保存、更正、重进，旧值不会作为现值复活。先完成[共用准备](./README.zh-CN.md)，使用 C-A 原咨询；不从旧“需求确认页”开始。

## 小程序步骤

| 用例 | 在同一咨询逐条发送 | 预期 |
| --- | --- | --- |
| AG02-01 独立字段 | “请记下：书房书桌靠窗，书房需要收纳”“请记下：客厅保留阅读角，全屋预算20万元” | 明确保存有真实回执；书房、客厅和预算分开保留 |
| AG02-02 多字段更正 | “更正：书房书桌改为靠内墙；全屋预算改为18万元。其他需求保持原样” | 当前书桌/预算更新；书房收纳与客厅阅读角不丢失；不能一部分失败却声称全部已存 |
| AG02-03 查询现值与历史 | “只回顾本次聊天：当前需求是什么，哪两项更正过？不要查业务资料” | 当前18万元/靠内墙；20万元/靠窗只作为旧说法，能找到对应原话 |
| AG02-04 假设不存 | “假设预算变为30万元，先比较一下，不要修改我的需求”，等回复后问“我当前预算记的是多少？” | 仍为18万元；假设不写入现值 |
| AG02-05 转述与否定 | “别人建议客厅拆掉阅读角，但我不同意，不要改我的需求”，再问当前客厅需求 | 仍保留阅读角，不能把他人建议当客户更正 |
| AG02-06 歧义 | “把另一间的书桌也改一下，先确认具体房间再记录” | 先澄清，不用“另一间”或空房间猜写 |
| AG02-07 重进 | 退出小程序，从“查看历史”进原咨询，再问书房/客厅/预算 | 与更正后一致，不因清本地展示/换页恢复旧值 |

若想从员工界面核对整理，客户点“找设计师”，D-A 从“小K咨询接管”接手后查看“需求”和“客户原话”。自动整理或员工“内部修正”不等于正式事实，不把所有 Agent 记忆字段必然映射成独立表单项。接待结束后继续客户检查。

## 房屋、版本与权限

- **AG02-08**：C-B 的乙屋也有书房，用 C-B 开本人咨询并保存不同需求。回 C-A 查询，不应出现乙屋值。同一客户多房屋、同名房间的复杂关联尚未完整；未明确绑定时应澄清，不能合并。
- **AG02-09**：按[完整流程第06步](./full-flow.zh-CN.md#06-发布精确方案并让客户决定)发布两版正式方案，只批准V2。自然语言“改书桌”只改获支持的客户需求，不自动改正式方案；旧版同意不能批准新版。
- **AG02-10**：先明确共享，再更正私有需求，分别询问当前意向和已共享内容；两者来源不同。撤回共享后，旧共享值不能冒充当前需求或被用于复活正式依据。

## 本阶段不能靠少量消息证明的内容

累计超过300条更正历史的归档、最多300个当前键、原子回滚、来源撤回覆盖归档及满载模型容量，需要开发在批准环境构造数据并核实服务记录。不要在手机上连发300次凑通过；普通更正/重进成功只完成本页用户可见部分。复杂复合字段和归档级语义检索仍属于剩余范围。

每条记下实际保存反馈、查询值和重进结果；若回复说“已保存”但读回不是该值，按失败记录，不能仅凭话术通过。维护依据：[Agent计划](../../xiaok-agent-engineering-plan.zh-CN.md)、[二期合同](../../xiaok-assistant-phase-2.zh-CN.md)的 AG-02 及更正来源合同。
