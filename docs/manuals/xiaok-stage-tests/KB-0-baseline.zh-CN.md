# KB-0 环境与测试资料基线

KB-0 是内部准备，不是一个独立客户功能页。目标是让后续手测使用同一套企业、账号、模型和可核对资料，避免拿空页或旧环境判断实现。先阅读[总说明](./README.zh-CN.md)及[合成资料](./test-materials.zh-CN.md)。

## 准备人员逐项操作

| 用例 | 操作 | 完成标准 |
| --- | --- | --- |
| KB00-01 版本与环境 | 记录小程序开发/体验版本、后台版本、服务地址、企业；请开发确认本轮服务代码与迁移 | 两端同环境，清楚手机是否包含当前阶段；未确认时为环境未就绪 |
| KB00-02 真实账号 | 使用C-A/C-B、D-A/M-A、T-A分别登录；核对“我的 → 当前身份”和后台选中企业 | 能区分不同真实人和同账号切身份；不用共享管理员凭据模拟客户 |
| KB00-03 业务关系 | 准备甲/乙客户档案、唯一活动项目、业主访问、书房/客厅、实际节点及成员 | C-A只见甲屋，C-B只见乙屋；成员可正常进入已分配工地 |
| KB00-04 服务依赖 | 由开发/管理员核对当前模型、Embedding/profile、Worker、企业能力和额度 | 可处理真实任务；不只核对配置字段“有值”。只记录名称/状态，不记录凭据 |
| KB00-05 知识录入 | T-A后台新建K-A/K-B/K-I及必要文件，索引/发布，填编号表 | 客户正文与内部资料范围分开，发布版本和原件可核对 |
| KB00-06 小程序正例 | C-A首页“和小K聊一聊”，问K-A主题，点来源，退出重进 | 实际回答/来源/持久化均可用；失败按当前结果记录 |
| KB00-07 后台试问 | T-A“管理员试问 → 新建试问”，范围选“客户可见资料”，问同主题 | 本人试问可用，范围正确；不用此结果替代客户Agent语义验收 |

建档、项目和账号若不存在，由准备人员在批准开发/隔离环境创建明确标记的合成数据，再进入后续测试。不要只留下“无数据，待用户补”的空页结果，也不要运行未知的旧fixture命令把真实客户当样本。本次文档编写没有执行这些写入。

## 本轮固定与可变内容

固定本轮核心题、必要/禁止来源、资料版本与项目状态；每次修订后在记录中另开一轮。先做无冲突正文基础，再增加条件冲突/撤回负例。需要开发绑定source/test/model配置hash的专项验收另行执行，手工记录不能冒称已完成hash绑定。

当前已知边界：DOCX、文字PDF及有界XLSX可测；扫描OCR、复杂表图、旧格式、影子profile切换和定时计划尚未交付。语音、完整图纸理解和生产容量也不属于本轮准备完成标准。

## 一次测试结束后的整理

在本轮编号表中标明哪些资料已撤回、哪些成员已移出、哪些咨询还在真人/等待状态。需要恢复后续用例时，明确结束接待、恢复授权并创建新的有效版本/核对；不要以复活旧失效依据代替恢复。只清理本轮合成数据；原始失败记录和未知调用交开发保留核实。

KB00-01～07完成后即可按[完整流程](./full-flow.zh-CN.md)开始。不要求先做大规模平台对比，也不把KB-0记为独立用户阶段已交付。依据：[知识计划](../../xiaok-enterprise-knowledge-plan.zh-CN.md)及[二期合同](../../xiaok-assistant-phase-2.zh-CN.md)。
