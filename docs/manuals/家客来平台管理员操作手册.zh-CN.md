# 家客来平台管理员操作手册

平台内部使用 · 仅限平台管理员与超级管理员

版本：2026-08-28

适用范围：家客来后台平台管理中心、跨企业运维与审核能力

适用对象：平台管理员（`admin`）、超级管理员（`super_admin`）

> [阅读提示] 本手册不是企业负责人的培训材料，也不是设计师、测量员的工作指南。平台管理员负责企业开通、平台配置、跨企业排查、权限和数据安全；日常获客、派单、预约、量房和方案交付应由 ToB 企业团队完成。

# 1. 平台管理员的工作边界

## 1.1 一句话职责

平台管理员要保证每家企业“能开通、能登录、能获客、能出图、能留痕”，并在出现跨企业或平台级问题时定位原因、保留审计记录、控制风险。

企业负责人只管理本企业的经营和客户；平台管理员才处理全局企业状态、平台供应商、平台码环境、系统角色、全局短信、媒体存储和跨租户诊断。

## 1.2 平台管理员不做什么

- 不用平台账号替企业员工联系客户、预约上门或完成量房。
- 不在后台直接编辑正式量房墙图；后台户型图库和量房记录是只读核验入口。
- 不把 `er_` 企业开户码发给普通员工，也不把企业负责人的 `ej_` 入驻码当成平台开户码。
- 不为了排查方便给企业账号增加平台菜单权限。
- 不把“业务写入成功”当成短信、微信订阅或外部供应商已经送达。
- 不在没有审批、备份和精确指纹时执行清理、整企清空或整企删除。

> [权限原则] 看到菜单不等于可以随意写数据。每次跨企业操作都先确认当前企业范围、对象、变更原因、影响范围和回滚方式。

## 1.3 平台后台工作域速查

| 工作域 | 常用入口 | 主要工作 | 关键边界 |
| --- | --- | --- | --- |
| 企业与开户 | 企业管理、企业开户码 | 审核、启用/停用、开户码 | 状态变更要填原因；全局同时只有一个 active `er_` 开户码 |
| 平台能力 | AI 供应商、生图模型、AI 点数价格、媒体存储 | 配置供应商、模型、点数和存储 | 凭据不回显；配置变化通常只影响后续任务 |
| 消息与环境 | 短信设置、通知记录、小程序码环境 | 短信、订阅消息、码环境和失败重试 | 外部发送失败不回滚业务事务 |
| 权限与审计 | 角色权限管理、系统管理、用户审计 | 账号、菜单、登录和操作留痕 | 按最小权限配置；不要删除替代停用 |
| 跨企业协助 | 运营工作台、线索转化、户型图库、量房记录、三方提成、设备管理 | 在指定企业视图排查业务 | 先选企业再操作，完成后切回“所有企业” |

# 2. 登录、企业视图与安全

## 2.1 第一次登录

1. 使用平台管理员后台账号登录电脑后台。
2. 首次登录按页面要求修改初始密码；登录密码为 6–32 位。
3. 确认左侧出现“平台管理中心”。如果只看到企业菜单，先确认账号角色和菜单权限。
4. 头像菜单可以修改登录密码和退出系统；平台管理员不使用企业安全密码代替登录密码。

平台管理员没有面向员工日常工作的微信小程序 Tab。需要复现小程序问题时，让对应企业员工在自己的身份下操作并提供页面、时间、线索或任务编号。

## 2.2 切换企业范围

1. 使用顶部企业选择器选择 `-- 所有企业 --`，用于总览和平台级配置。
2. 处理单租户问题时选择具体企业；进入线索、户型、量房、提成或设备页面后，再确认页面标题和筛选范围。
3. 只读排查结束后切回 `-- 所有企业 --`，避免下一次误把操作写入上一家企业。
4. 如果接口提示“请先选择企业”，说明当前页面需要租户上下文；不要通过旧链接或手工改 URL 绕过选择。

## 2.3 安全操作习惯

- 账号、API Key、对象存储密钥、短信密钥不得复制到群聊、截图或培训资料。
- 处理客资导出、危险清理和整企操作时，按页面要求使用安全校验并保留审批编号。
- 任何拒绝、停用、重置、权限扩大、重试和清理操作都要写清原因。
- 发生不确定的跨企业问题时，先只读检查和截图记录，不要连续点击多个写操作。

# 3. 企业审核与生命周期

## 3.1 审核新企业

1. 进入“平台管理中心 → 企业管理”。
2. 找到状态为“待审核”的企业，核对企业名称、联系人手机号和申请资料。
3. 资料合格时执行“通过”。系统会创建或绑定企业负责人账号，初始密码为 `123456`。
4. 资料不合格时执行“拒绝”，必须填写 4–200 字原因；需要补资料时，让申请人修改后重新提交。
5. 审核后通知企业负责人使用后台账号或企业入驻流程登录；以后台状态为准，不以短信/微信是否送达为准。

## 3.2 状态和处理方式

| 状态 | 通俗解释 | 平台管理员动作 |
| --- | --- | --- |
| `pending_approval` | 正在审核 | 核资料，执行通过或拒绝 |
| `active` | 可正常生产 | 允许企业负责人登录和使用小程序 |
| `disabled` | 暂停使用 | 查清欠费、违规、迁移或安全原因后再启用 |
| `rejected` | 审核未通过 | 补资料后重新提交审核 |

“拒绝”和“停用”必须写 4–200 字原因；每次状态变更都会写企业状态事件。不要用删除企业或删除负责人代替停用。

## 3.3 企业负责人账号与入驻

- 审核通过时，系统会创建或绑定企业负责人账号；新账号初始密码为 `123456`。
- 企业员工通过企业侧 `ej_` 入驻码加入，企业负责人在企业自己的“入驻码”页面管理该码。
- 平台 `er_` 开户码只用于企业开户，不用于员工入驻。
- 非 `active` 企业会阻断商户后台登录、企业员工小程序上下文和推荐人企业关系。

# 4. 平台码与小程序环境

## 4.1 企业开户码 `er_`

1. 进入“企业开户码”，查看当前全局有效的 `er_` 码和近期审计。
2. 需要更换时点击“换新”，可设置过期时间；旧码立即失效。
3. 需要停止发放时点击“停用”；停用不会删除已创建企业。
4. “查看/下载图片”只生成当前有效码的私有图片，不会自动换新。
5. 全局同一时间只保留一个 active 开户码；发放前确认接收对象和有效期。

## 4.2 小程序码环境

1. 进入“小程序码环境”。
2. 选择 `develop`、`trial` 或 `release`。
3. 保存后只影响之后生成的企业入驻码、推荐推广码和员工活动码，不改写已下载或已分发的历史图片。
4. 发生“扫码进入旧版本”时，先核对码生成时间和当时环境，再判断是否需要重新生成。

## 4.3 三类码的区别

| 码 | 用途 | 管理位置 | 是否能替代其他码 |
| --- | --- | --- | --- |
| `er_` 企业开户码 | 开通企业 | 平台“企业开户码” | 不能替代员工入驻码 |
| `ej_` 企业入驻码 | 企业员工/推荐人加入 | 企业负责人“入驻码” | 不能开新企业 |
| 员工活动码 | 客户扫码留资 | 员工/企业工作台 | 不能开企业或加入员工 |

# 5. AI、消息与媒体平台配置

## 5.1 AI 供应商、模型和点数

1. 在“AI 供应商”检查供应商是否启用、连接配置和默认模型映射。
2. 在“生图模型”只启用平台目录中确实可用的模型。
3. 在“AI 点数价格”设置动作价格、模型和分辨率价格；保存前检查点数范围和生效对象。
4. 模型要出现在企业设计工作台，通常还需要至少一档有效点数价格，并且企业侧 AI 能力已开放。
5. 生成失败时记录企业、工作流、任务编号、错误时间和供应商返回；可在 AI 工作台重试，不要反复创建空白方案。

平台凭据不会在页面回显。供应商不可用时，先判断是平台配置问题、企业能力开关问题，还是单次任务失败。

## 5.2 通知和短信

1. 在“通知记录/工作流日志”确认站内通知、小程序订阅消息是否生成。
2. 在“短信设置”选择阿里云或腾讯云并保存平台配置；先在供应商控制台完成签名、模板和手机号审核。
3. 用“发送测试”验证配置，再观察短信送达记录。
4. 失败记录符合条件时可重试；短信失败不会回滚派单、预约或其他已完成业务事务。
5. 对外通知异常时，先给企业负责人说明“业务状态”和“消息状态”是两件事。

## 5.3 媒体存储和数据维护

1. 在“媒体存储”检查对象存储、七牛展示 URL 开关和运行状态。
2. 备份前确认数据库连接、备份目录和操作者身份；恢复演练只使用专用演练库。
3. 清理前先执行 dry-run，查看候选清单、目标指纹和 SHA-256。
4. 只有在审批通过、清单审核完成、指纹精确匹配且显式打开本地正式库开关后，才执行清理。
5. 清理命令本身不会替你删除七牛对象；外部对象删除要走单独审核流程。

> [高风险] “清空并重跑入驻”和“删除整家企业”可能不可恢复。生产环境默认拒绝；没有审批、备份和书面确认时不要操作。

# 6. 角色权限与用户审计

## 6.1 维护角色菜单

1. 进入“角色权限管理”，按“平台管理中心、B2B 运营转化、运营工作台、推荐网络、户型图库、AI 辅助设计、团队资产管理”分组查看菜单。
2. 修改角色时优先点击“恢复该角色默认”，再按最小权限原则勾选例外菜单。
3. 记住子入口复用父权限：企业开户码复用“企业管理”；入驻码、推荐人和预约设置复用“推荐网络/运营工作台”。
4. 权限变更后让账号刷新 `/api/auth/me`；通常不需要重新登录。

## 6.2 平台账号和用户审计

- “系统管理”用于维护平台后台账号；“用户审计”用于核对用户、微信身份、企业绑定和登录线索。
- 账号异常时先核对角色、企业范围、最近状态事件和登录时间，再决定是否停用。
- 不要直接删除仍有关联业务的员工或管理员；删除可能被预约、AI 操作记录或历史提成阻止。
- 平台账号不属于企业小程序员工工作台角色，不能用平台账号代替设计师或测量员复现业务。

# 7. 跨企业业务协助

## 7.1 线索、预约和提成

1. 先在顶部选择具体企业，再进入“线索转化”或“运营工作台”。
2. 只读核对线索归属、设计顾问、现场顾问、预约、正式户型和客户可见方案。
3. 涉及改派、预约、签约、结案或提成时，先确认企业负责人的授权和工单记录。
4. 已签约线索改运营归属不会重写既有提成快照；调整提成金额或受益人必须填写原因。
5. 处理完成后回到“所有企业”，并在交接记录写清企业、客户、动作、结果和时间。

## 7.2 正式量房和户型

- “户型图库”只读查看正式 v4 墙图、空间、开口和更新时间。
- “量房记录”用于查看手动/BLE 测量审计，包括人员、设备、来源、方向、数值和时间。
- 正式 BLE 量房只能由已派现场顾问在小程序 `surveying-editor` 完成；平台管理员不能代画墙体。
- DXF 导出需要正式 v4、状态 `completed` 且至少有一个闭合空间；草稿和无效户型不能导出。

# 8. 设备授权与平台故障排查

## 8.1 BLE 测距仪

1. 在“设备管理”新增或编辑设备，录入 `deviceId`/MAC 或设备编码，以及可选的 SN 码。
2. 需要清理多台设备时，在列表勾选后使用“批量删除”。
3. 按 SN 查找设备时，使用列表「SN 码」搜索，可输入部分字符并省略横线或空格。
4. 确认设备状态为 `assigned`，并分配到正确企业。
5. 员工反馈“未授权”时，先核对设备企业、员工企业和设备身份；再让现场顾问检查蓝牙、附近设备权限、电量和距离。
6. 不要仅凭手机显示名判断设备身份；以协议规定的设备身份和后台绑定为准。 SN 码只作库存登记，不参与蓝牙授权。

## 8.2 平台级故障判断顺序

1. **身份问题**：账号角色、企业状态、企业选择器和权限菜单是否正确。
2. **业务数据问题**：线索/预约/户型/提成是否已写入，状态是否符合闭环条件。
3. **供应商问题**：AI、短信、微信、对象存储是否返回错误或超时。
4. **客户端问题**：只在对应企业员工身份下复现小程序页面，不用平台账号越权代操作。
5. **审计问题**：记录接口、时间、企业、对象编号、错误码、处理动作和最终结果。

# 9. 每日巡检与交接

## 9.1 每日巡检清单

- 待审核企业和异常状态企业是否都有负责人及处理原因。
- 企业开户码、平台小程序码环境和企业双码是否在有效期内。
- AI 供应商、模型、点数价格、媒体存储和短信配置是否出现异常。
- 短信/订阅消息失败是否有可重试记录，是否影响关键通知。
- 设备是否误分配企业，是否出现大量“未授权”反馈。
- 权限变更、企业停用、危险操作和数据清理是否有审批或审计记录。
- 跨企业排查结束后是否切回“所有企业”。

## 9.2 交接记录模板

每条平台问题至少写清：

1. 企业名称或“平台全局”。
2. 账号/角色和当前企业视图。
3. 客户、预约、任务、工作流或设备编号。
4. 发生时间、页面/接口、错误信息和原始截图位置。
5. 已执行的只读检查、写操作、审批编号和通知对象。
6. 当前状态、下一步负责人和预计复查时间。

## 9.3 平台管理员交接标准

- 能审核、拒绝、停用和重新启用企业，并能说明原因留痕要求。
- 能区分 `er_` 企业开户码、`ej_` 企业入驻码和员工活动码。
- 能独立排查 AI、短信、媒体、设备、权限和小程序码环境问题。
- 能维护平台角色菜单并完成一次用户审计查询。
- 能说明备份、dry-run、清理和整企危险操作的审批边界。
- 能把企业、账号、编号、时间、错误、动作和结果写入交接记录。

# 10. 平台管理员专用边界与事实来源

- 本手册仅供平台管理员和超级管理员使用，不作为 ToB 企业负责人、设计师或测量员培训材料。
- 平台管理员不通过小程序开展日常经营；小程序端的设计、量房、预约和收益页面属于企业员工或客户身份。
- 本手册以当前代码、平台菜单权限和后台模块清单为准：`docs/admin-system-modules.md`、`docs/admin-system-modules.zh-CN.md`、`admin/src/config/admin-routes.ts`、`admin/src/lib/admin-user-roles.ts`、`admin/src/components/Sidebar.tsx`。
- 企业审核、平台配置、外部供应商和危险维护能力均受服务端权限、租户范围、环境开关和审计约束；历史路线图不能证明能力已上线。

手册结束。平台新增路由、权限、供应商或危险操作后，应先更新本手册，再安排平台内部培训。
