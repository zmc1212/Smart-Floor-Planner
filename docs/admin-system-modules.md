# Admin System: Current Module Inventory

Formal floor-plan PUT mutations use the same linked-lead responsibility boundary as Mini Program reads: the currently assigned designer or measurer may continue and complete a plan originally saved by the other field role, subject to the shared enterprise boundary.

This is the current Admin runtime inventory. It records stable entry points,
contracts, permissions, and limitations only. Implementation history belongs in
Git commits; do not append dated change logs here.

The AI workbench and lead-detail publication surfaces expose finalization once
at the workflow/scheme level. Finalization marks the customer-primary scheme and
does not freeze later generation; the shared finalize endpoint requires an active
customer-visible publication. Finalize and automatic unfinalize events are
recorded in `leadLifecycleEvents`, and withdrawing the last active publication
clears the finalized pointer. The existing tenant and assigned-designer /
enterprise-admin permission boundary remains unchanged.

## Shared architecture

AI workflow automatic floor-plan binding (Implemented): `GET /api/ai/workflows` and `GET /api/ai/workflows/[id]`, together with their Mini Studio counterparts, persist a missing `sourceFloorPlanId` when an active workflow's unarchived lead has an eligible primary formal plan. Without a primary pointer, only one eligible linked plan permits automatic binding; an invalid primary or multiple eligible plans leaves the workflow unbound. Eligibility still requires completed formal v4 data with a usable closed space. This is lazy reconciliation on the next list/detail read, not a background migration or a survey-save notification. A conditional NULL-only update preserves existing bindings, source image/role, activity timestamps, historical generation/batch snapshots, and publications. Existing tenant and role boundaries apply; Mini detail/rename checks lead access before reconciliation. The existing workbench floor-plan preview/link and Mini whole-house configuration consume the repaired binding; no UI layout, style, asset, or mode switch is introduced. Verification: focused eligibility/serialization tests and local PostgreSQL list/detail reconciliation, persistence, no-overwrite, and cross-tenant tests pass. Visual source: existing Admin workbench contract and Mini Composer `design-references/ai-design/unified-entry-v2/21-studio-composer-v4-three-states.png`; ESLint (0 errors; existing warnings) and production build pass; runtime verification remains pending the user's screenshots after deployment.

AI workbench floor-plan preview cache contract: the current formal floor-plan snapshot asset version is included in the `/ai-studio/scenarios` preview URL, so a measurement update cannot remain hidden behind a browser image cache. Historical generation batches keep their original control-image asset for reproducibility. The workbench composer exposes `whole_floor_plan` and `single_room_photo` modes; the latter skips the control image and requires an explicit `sitePhotoAssetIds` entry (a `styleReferenceAssetId` template cover never qualifies), while the former preserves the formal control-image contract. `GET /api/ai/workflow-leads/[id]/site-photos` is the tenant-scoped, read-only Admin picker source for the current lead's active persisted site photos; the workbench reuses their media asset IDs directly as generation references.

## Module inventory

Professional endorsements are an implemented tenant-scoped staff capability. Enterprise and platform administrators use `GET/PUT /api/professional-profile-settings` from `/staff` to set designer/measurer default titles, default experience years, a service threshold of at least 100, forced enterprise content, and `follow_staff` / `force_show` / `force_hide` title visibility. They use `GET/PATCH /api/staff/[id]/professional-profile` for a staff-specific title override, career year, title preference, profile lock, and exact-count opt-in. Designers and measurers use `GET/PATCH /api/miniprogram/staff/professional-profile` for unlocked self-service fields. Customer DTOs receive only the resolved `professionalProfile` using the stored title text (no 设计师/测量员 rewrite). The service-archive GET resolves designer and measurer slots independently, so one person assigned to both cards uses each role's enterprise default title and experience copy. Raw counts remain internal. Designer counts are distinct leads with a customer-visible publication credited to the designer at publish time; measurer counts are distinct leads with a completed formal v4 floor plan owned by the measurer. Counts at or below the enterprise threshold never leave internal/Admin responses, and exact display is available only above that threshold. These fields do not change assignment eligibility.

Service-address completion is part of the appointment service fact. `measurement_appointments` stores the manual service address plus optional `location_name`, bounded GCJ-02 latitude/longitude, and coordinate system. Appointment and lead DTOs rewrite PostgreSQL `tstzrange` text (`2026-08-23 01:00:00+00`) to ISO-8601 (`2026-08-23T01:00:00.000Z`) so Mini Program `Date` parsing can place visits on the Asia/Shanghai calendar day. `GET /api/appointments/availability` omits past starts and, when the lead already has a confirmed appointment, excludes that row so same-day reschedule can pick an overlapping replacement; other leads still treat the measurer as busy. `POST /api/appointments` and `POST /api/appointments/[id]/address` accept that optional map location; address updates remain versioned and write previous/new location snapshots to the `address_updated` audit event. Mini Program callers are resolved as staff first (`staff._id` vs assigned designer/measurer); Admin cookie JWT remains the fallback. The Admin lead drawer and Mini Program appointment detail use the same entry. Creating or updating a service address copies an empty lead `communityName` in the same transaction from the map `locationName` when present, otherwise the typed address (trimmed to 160 characters; no overwrite). Mini Program appointment detail still offers staff an explicit sync for historical empty communities. `POST /api/appointments/[id]/complete` additionally requires a linked completed formal v4 survey floor plan with at least one closed space and returns `appointment_survey_required` (409) otherwise. Editor submit only stores the formal plan; lead `designing`, designer survey-completed notify, and slot release happen only after appointment-detail confirm-complete.

## Commission boundary

The measurer-designer acquisition contract is retired and retained only as a
record in [`measurer-designer-acquisition.md`](./measurer-designer-acquisition.md).
Referral-network signing commissions are governed by this inventory and the
development plan. Conversion snapshots three payable rows for `referrer_network`
and two rows for `staff_activity` or `manual_entry` (designer + measurer; the same beneficiary may
own both). `POST /api/lead-commissions/mark-paid` and the Mini Program mirror accept
one or more `{ commissionId, paidAmount }` entries; one tenant transaction locks every

decimal places. Paid and voided rows cannot be adjusted directly. Reverting conversion
stores the complete voided-row snapshot in lifecycle-event metadata; re-signing refreshes
the rows under the new contract, current rules, and current beneficiaries and returns them
to payable. The Admin and Mini Program payable-row UI is role-neutral, including
referrer rows, and exposes one **确认打款** action: its dialog pre-fills the current
