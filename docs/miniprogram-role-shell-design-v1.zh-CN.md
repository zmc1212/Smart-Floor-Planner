# 小程序五角色信息架构与角色外壳设计源 v1

状态：`已获实施授权，阶段实施中`  
适用阶段：推荐网络与预约计划第 12 阶段  
设计模式：Operate（高频业务操作）  
目标视口：iPhone 13 Pro，`390x844`，包含原生微信右上角胶囊和底部安全区

## 1. 交付边界

本文件是第 12 阶段的生产 UI 设计源。用户已明确授权沿用当前小程序风格实施角色外壳；
实施者必须先按本文件逐路由实现，再在中英文还原台账中替换对应行；只有完成 `390x844`
原生宿主核验后才能把路由标记为已还原。

本阶段只确定：

- 五个角色的默认落点、首屏信息层级和动态 TabBar 白名单。
- 身份选择、推荐人企业切换、会话失效/撤权恢复的页面状态。
- 每个角色的首次进入、真实有数据、空状态、加载、可重试错误和无权限状态。
- 原生胶囊/底部安全区几何、文字/触控下限以及现有深层设计源映射。

原始角色外壳阶段不生成假数据，也不替换已批准的预约、客户项目、推广服务码和正式量房
深层页面。第 14 阶段只为这些外壳入口补充当前签名身份的服务端工作台只读聚合，不创建
新的客户、预约、量房、方案或收益业务合同。

当前实施复用四个静态 Tab 路由作为签名角色外壳：客户为“服务/项目/我的”，推荐人为
“推广/客户/收益/我的”，设计师为“工作台/客户/设计/收益/我的”，测量员为“工作台/客户/收益/我的”，
企业负责人为“经营/客户/预约/我的”。每个工作区只读取当前签名身份的服务端聚合；测量员
只能从已指派任务进入唯一正式量房编辑器，绝不以空白或模拟 Tab 占位。

角色主场景复用批准的角色外壳画板所引用的独立完整小 K 资产
`miniprogram/images/page-ip-v3/mine.png`，不是从画板切割的页面图像。

## 2. 视觉方向与安全区合同

### 2.1 结构方向

- 页面采用暖白背景、一个浅薄荷绿色的业务主场景和真实数据工作区；主场景只占首屏
  约 `18%–24%`，不做营销 Hero。
- 小K只承担当前身份的业务动作：客户是“服务向导”，推荐人是“推广管家”，设计师是
  “方案协调者”，测量员是“测量搭档”，企业负责人是“调度观察员”；“我的”是“身份管家”。
- 主场景使用 F1 完整角色体块和 F3 空间展开隐喻，列表、统计和按钮仍使用真实原生控件。
- 不使用截图切片、整页背景图、圆形角色底座、渐变光晕或不存在的快捷能力。

### 2.2 `390x844` 元素几何

| 区域 | 约束 |
| --- | --- |
| 原生胶囊保护区 | `x=270..390px`、`y=0..88px` 视为不可放置区；标题、返回、保存、切换和任何可点击元素不得进入。 |
| 自定义导航 | 使用运行时 `navigationTop/navigationRight`；标题和动作从胶囊左侧开始，不通过胶囊居中。静态稿以 `y>=96px` 的应用内容线作为验收参考。 |
| 首屏业务场景 | 自定义导航下方约 `18%–24%` 视口高度；必须露出第一个真实数据区或唯一 CTA。 |
| TabBar | 固定在底部，内容区域至少预留 `128rpx + env(safe-area-inset-bottom)`；底部手势区不承载文字或按钮。 |
| 文字 | 主标题/业务值/主按钮/正文不低于 `24rpx`；辅助信息不低于 `20rpx`。 |
| 触控 | 可点击元素逻辑高度不低于 `44px`，禁用态仍保留清晰原因。 |

## 3. 五个默认落点

| 角色 | 运行时落点 | 首屏隐喻与主任务 | 允许的真实数据 | 禁止出现 |
| --- | --- | --- | --- | --- |
| 客户 | `/pages/index/index` | 服务向导展开“我的装修服务”，先看服务阶段、当前预约和下一步 | 本人线索的服务状态、当前预约、完成的 v4 户型摘要、已发布方案 | 员工线索池、BLE、正式量房编辑、AI 生产工具、签单/提成管理 |
| 推荐人 | `/packages/business/referrer-workbench/referrer-workbench` | 推广管家打开“企业服务台”，先选当前企业并展示服务码 | 当前成员关系、活动服务码状态、脱敏里程碑、本人提成状态 | 手机号、微信号、精确地址、户型 graph、内部预约原因、企业规则 |
| 设计师 | `/pages/index/index`（角色工作台） | 方案协调者整理“待推进客户档案”，优先处理下一项真实协作 | 本人被派线索、预约摘要、完成户型摘要、本人成功生成及发布状态、本人提成状态 | 他人线索、测量员请假、企业提成配置、无项目约束的量房入口 |
| 测量员 | `/pages/index/index`（角色工作台） | 测量搭档打开“今日测量台”，先看预约和可服务时间 | 本人预约、不可用时间、已指派量房任务、正式量房入口、本人提成状态 | 设计发布、签约、推荐人收益、企业规则、未指派客户 |
| 企业负责人 | `/pages/index/index`（角色经营） | 调度观察员查看“经营看板”，先处理异常和待审批事项 | 当前租户异常、客户摘要、预约异常、已有授权签约/审批入口、本企业提成发放台账 | 直接继承设计师/测量员工具；需要实操必须切换身份 |

受微信静态 Tab 数量限制，阶段 14 在 `/pages/index/index` 呈现负责人“经营”首屏；
`/pages/mine/mine` 保持身份与账号管理，不再作为负责人默认首页。

## 4. 角色白名单 TabBar

TabBar 由服务端 bootstrap 的 `current.capabilities` 生成；客户端隐藏、深链守卫和服务端
授权必须一致。不存在共享的固定中央“量房”按钮，只有测量员显示量房主入口。

| 角色 | 顺序与文案 | 入口能力 | 徽标来源 |
| --- | --- | --- | --- |
| 客户 | `服务 / 我的` | `customer.service`、`account` | 服务端本人待预约/待改期/待重约计数；失败显示“暂时无法读取”。服务首屏直达档案，「免费效果图」进入交付方案册；`customer.projects` 仍守卫档案/列表 API，`customer-projects` 仅为重定向壳 |
| 推荐人 | `推广 / 进度 / 收益 / 我的` | `referrer.promotion`、`referrer.progress`、`referrer.earnings`、`account` | 当前成员关系的脱敏里程碑和收益状态；不显示客户数量猜测 |
| 设计师 | `工作台 / 客户 / 设计 / 收益 / 我的` | `staff.leads`、`staff.appointments`、`staff.design`、`staff.earnings`、`account` | 本人待跟进/预约/发布状态及本人待支付提成；无数据不显示假数字 |
| 测量员 | `工作台 / 客户 / 收益 / 我的` | `staff.schedule`、`staff.tasks`、`staff.earnings`、`account` | 工作台 Tab 聚合今日预约；“客户”Tab 复用共享的 `leads-management` 线索列表（按角色收窄、不可新增）查看已派/推广相关客户与跟进交接状态；“收益”Tab 展示本人待支付/已支付提成；量房相关深层编辑器仍由任务上下文触发 |
| 企业负责人 | `经营 / 客户 / 预约 / 提成 / 我的` | `enterprise.operations`、`enterprise.customers`、`enterprise.appointments`、`enterprise.commissions`、`account` | 当前租户异常/审批/预约异常及待支付提成笔数；不混入员工个人待办 |

当前项使用品牌绿和浅薄荷底，其他项使用中性灰；图标使用现有本地授权图标集。已确认的
`design-references/tabbar-icons/tabbar-earnings-appointment-v1.png` 映射为：收益和提成使用
同构的 `tab-earnings` 钱包收入图标对，企业负责人「预约」使用同构的 `tab-appointment`
日历确认图标对；每对均具有中性灰和品牌绿状态。推荐人工作台内选择企业，不在 TabBar
额外增加企业项。

## 5. 身份选择与恢复状态

| 状态 | 页面必须表达 | 唯一主要动作 | 数据边界 |
| --- | --- | --- | --- |
| `loading` | “正在确认当前身份”与稳定骨架 | 无；等待 bootstrap | 不渲染旧角色内容或本地徽标数字 |
| `single-context` | 当前角色、企业/成员关系和进入按钮 | 进入默认落点 | 只显示当前有效上下文 |
| `multi-context` | 身份卡按角色分组，当前项明确标记 | 选择身份并确认切换 | 只展示服务端返回的有效上下文 |
| `referrer-memberships` | 推荐人角色只出现一次，企业选择在推广工作台内完成 | 选择企业并切换签名成员关系 | 不把其他企业数据带入当前请求 |
| `expired` | “登录已失效，请重新确认身份”及原因摘要 | 重新登录 | 清除失效 token，不泄露失效企业 |
| `revoked` | “当前身份已不可用”及仍有效身份列表 | 选择有效身份或退出 | 不静默回落客户页 |
| `forbidden-deep-link` | “当前身份无法访问此页面” | 返回当前角色首页 | 不发起越权 API 请求 |
| `switch-error` | 保留当前页，说明切换失败 | 重试切换 | 不改变当前有效 token |
| `no-alternate` | 当前身份已是唯一有效身份 | 返回“我的” | 不制造无意义切换流程 |

“我的”首屏直接展示当前角色和企业。身份切换入口不再隐藏在设置齿轮；仅一个身份时仍
展示当前身份，但不显示可点击的切换箭头。

## 6. 关键空状态源

每个空状态只保留一个解释和一个真实 CTA，小K执行与角色一致的动作，不展示本地模拟数量。

| 角色/页面 | 空状态文案方向 | 小K动作 | CTA |
| --- | --- | --- | --- |
| 客户服务 | “还没有进行中的服务” | 服务向导展开一条空的房屋路径 | 查看领取服务入口（仅在真实入口可用时显示） |
| 客户项目 | “完成服务后，项目会出现在这里” | 小K整理空项目册 | 返回服务 |
| 推荐人推广 | “先选择一个已加入的企业” | 小K把服务码放入企业台 | 选择企业 |
| 推荐人进度/收益 | “暂时还没有可展示的服务事实/收益记录” | 小K查看空白里程碑夹 | 返回推广 |
| 设计师客户 | “当前没有已派客户” | 小K整理空档案页 | 刷新 |
| 设计师设计 | “完成正式量房后才可开始方案” | 小K展开但不填充的方案册 | 查看待完善客户 |
| 测量员日程/任务 | “今天没有已确认安排/待交接任务” | 小K收起测距仪 | 查看不可用时间/刷新（按真实入口） |
| 企业经营 | “当前没有需要处理的异常” | 小K观察一条平稳的调度路径 | 刷新 |
| 身份列表 | “当前账号只有一个有效身份” | 小K守护当前身份牌 | 返回“我的” |

## 8. 批准后的验收清单

- 五个落点和 TabBar 顺序与上表完全一致，服务端能力缺失时不显示入口。
- `390x844` 截图中标题、操作、胶囊和底部手势区无重叠；窄屏 `<=360px` 无文字溢出。
- 每个角色至少核验首次进入、有数据、空、加载、可重试错误、失效和无权限状态。
- 徽标仅来自 bootstrap 的真实角色范围计数；未知/失败不以 `0` 或示例数字替代。
- 深链负向路径在客户端、导航守卫和 API 权限三层均拒绝，不渲染旧角色界面。
- 每个实际修改的运行路由在中英文设计还原台账中只保留一行，并附原生宿主截图证据。

## 9. 实施与验收状态

用户已授权直接沿用现有小程序风格。第 12 阶段已落地 bootstrap 角色白名单导航、不泄露
失效企业数据的身份恢复页，以及按当前身份待办计数的服务端 Tab 徽标；失败显示「暂时无法读取」，
不以本地 0 占位。客户服务首屏、企业经营异常台、预约 Tab、测量员工作台和设计师
资料自助已消费共享 `serviceStage`/`nextActionKind`；各路由还原台账仍须等待 `390x844`
原生宿主核验后才可更新。
