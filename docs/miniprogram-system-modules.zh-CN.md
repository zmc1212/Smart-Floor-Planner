# 小程序当前功能清单

本文档记录 `miniprogram/` 原生微信小程序的当前实现。事实基线是当前
`app.json`、页面处理器、共享工具和实际调用的后台 API。

## 状态与运行环境

- `Implemented`（已实现）：页面及其真实数据/操作链路可用。
- `Limited`（有限支持）：依赖登录、企业角色、蓝牙硬件、供应商或特定正式墙图形态。
- `Placeholder`（占位/未开放）：只有 mock/本地行为、规划 toast 或没有真实服务端操作。
- 运行环境：原生微信小程序；`utils/api.js` 通过 JWT Bearer 请求；`threejs-miniprogram` 用于 3D 预览；可选蓝牙激光测距仪。
- 主 Tab：首页 `index`、客户线索 `leads-management`、设计 `ai-design`、我的 `mine`，另有自定义中置量房操作。登录、详情、工作流、灵感库、推荐和正式量房为次级页面。

## 身份与共享上下文

- `/pages/login/login`：通过 `/api/auth/miniprogram` 支持微信手机号快捷登录和账号密码登录，将 JWT/用户信息恢复到本地。
- 访问仅限员工：账号密码登录必须匹配启用中的后台 `AdminUser`；微信 code/手机号登录必须通过已绑定 OpenID 或后台手机号匹配启用中的 `AdminUser`。未匹配的外部用户会收到 `403`，无法建立小程序已登录业务会话。账号、绑定身份、企业和权限解析已切换 PostgreSQL，并在刷新和请求上下文解析时复核启用状态。
- `app.js`：恢复会话，解析二维码 `enterpriseId`/`staffId` 推荐参数，同步员工专业上下文、企业品牌，并对已记忆设备尝试静默 BLE 重连。
- `utils/api.js`：携带 Bearer token，通过显式 `ACTIVE_API_ENVIRONMENT`（`local` 或 `production`）选择唯一 API 地址，401 时清理会话并提示重新登录。请求不会跨环境回退，也不读取持久化 `apiBaseUrl`。
- 状态：PostgreSQL 登录与上下文恢复为 `Implemented`；具体路径仍依赖有效微信授权、账号、API 地址和企业/供应商配置。Phase 3 期间为 `Limited`：仍由 MongoDB 支撑的 AI 生成/媒体与商业工作流域要等计划内 PostgreSQL 切换后才兼容 bigint 身份；线索、正式户型、测量和设备绑定现已使用 PostgreSQL。

- 页面：`pages/index/index`。
- API：`/api/miniprogram/home`、`/api/floorplans`、户型 POST/PUT、`/api/leads/[id]`、`/api/location/reverse`、`/api/users/me`。
- 已实现：首页统计、定位/城市、按角色过滤的最近云端户型（本地草稿存在时仍显示，且可直接进入正式量房编辑器）、留资弹窗、BLE 连接状态、记忆设备自动连接、新建/继续正式量房、房间进入、企业员工常驻 AI 设计快捷入口，以及首页直达客户线索和 BLE 配对的快捷入口。

### AI 设计与企业点数

- 页面：`pages/ai-design/ai-design`、`pages/ai-design-create/ai-design-create`、`pages/ai-design-result/ai-design-result`、`pages/ai-design-history/ai-design-history`；旧 `pages/ai-gen/ai-gen` 仅兼容跳转。
- 导航：`pages/ai-design/ai-design` 已作为 `设计` 主 Tab，使用 `navigationStyle: custom` 实测微信胶囊和安全区，将页面标题与点数融入空间首屏，不再渲染居中的微信默认标题栏；同时继续使用共享固定自定义 TabBar 的页面高度、滚动与下拉刷新契约。首页、我的和旧兼容入口会先通过 `utils/aiDesignNavigation.js` 传递户型、房间、线索、范围和方案上下文，再调用 `switchTab`，以符合微信 Tab 页不能通过 `navigateTo` 查询参数进入的限制。
- API：小程序 AI 能力、按角色过滤的正式户型/房间来源、由正式墙图派生的标准化墙体/房间导航只读模型、当前完整户型 3D 导航预览状态、当前上下文可见活动方案、媒体上传/签名读取、任务创建/执行/状态/重试、历史读取/删除；`utils/aiDesignService.js` 统一携带 Bearer JWT。
- 目标上下文：选择户型后的方案查询统一使用 `floorPlanId + targetScope + roomId`（仅 `whole_floor_plan` 省略 `roomId`），并返回状态为 `missing | processing | ready | stale | admin_handoff` 的 `targetContext`。单房间成果必须同时匹配同一正式户型、`single_room` 和相同 `roomId`；全屋成果及缺少范围字段的旧任务不会自动填入房间。若全局已采用成果与目标精确匹配则优先使用，否则使用最新的精确成功成果；早于 `FloorPlan.updatedAt` 的成果仅保留在历史中，不自动续接。
- 已实现：企业共享 AI 点数与业务动作价格展示；首页改为沉浸式空间导航，同时保留“参考图复刻、空间换风格、户型生成、软装深化”四项真实任务。选择正式户型后，页面从 version-4 量房墙图派生可导航墙体、房间和完整户型/单房间目标，展示“空间基准、风格方案、软装完善、提案深化”四阶段方案旅程，并只突出一个上下文相关的“下一步”。当前有效且带有当前 `cutaway-v1` 导航渲染契约标记的完整户型成功结果会直接复用为 3D 导航封面；生成中的结果展示实时进度；缺失或早于户型最新更新时间的结果回退为确定性的正式 2D 墙图，并提供会明确消耗点数的生成/重新生成操作。页面不会为了预览自动创建付费任务。未选择正式户型时，默认入口使用室内场景游览；“参考图复刻、拍照换风格、户型生成、软装搭配”四个无序号空间锚点使用现有 AI 图标，表示可独立进入的能力，而不是必须依次完成的步骤。锚点会维护当前导航状态，平滑推近/移动视野，并用“上传参考图、拍照开始、选择户型、上传空间图”等明确动作同步更新确认后的“下一步”；真正的方案顺序只由下方阶段轨道和服务端推荐动作表达。选择后的 `leadId`、`floorPlanId`、`targetScope` 和单房间可选 `roomId` 由四种任务共同继承，只有户型生成强制要求先关联。完整户型一次生成一张带家具、抬高等距视角且移除顶面的 3D 剖切概念图，单房间一次生成一张室内视角概念图；不批量逐房间生成。首页紧凑方案卡会自动带入唯一活动方案，多个方案时要求用户选择，并保留“新建备选方案”；创建页、结果页和历史记录显示客户/方案归属、设计范围及“已同步方案/独立任务”。参考图复刻的输出比例跟随参考图；关联正式户型时，服务端将所选完整户型或隔离后的单房间控制图作为第一张墙体/门窗结构输入，将参考图作为第二张镜头、画幅、构图与风格输入，不再要求额外上传空间图；未关联户型时继续使用“参考图第一、空间图第二”。整体换风格和软装深化则跟随空间图比例并使用后台风格预设；完整户型保持方图，单房间默认横图。页面支持相册/拍摄上传，按文件签名字节校验微信 multipart 图片，上传失败时保留稳定的本地预览并支持原位重试；同时支持异步供应商任务状态、任务失败重试/点数释放、按输出比例展示且以参考构图为复刻对比源的可拖动分割线、预览、分享，以及等待相册写入完成并在权限被拒时引导进入微信设置的真实图片保存，另有历史复用和删除。详情读取会对生成中的任务强制查询上游状态；首页“最近方案”会把 `created`、`pending`、`processing` 三种未终态任务置于其他状态之前，以绿色数字显示真实阶段进度且不伪造最低百分比，各状态组内仍保持时间倒序，每 5 秒刷新直至可见任务成功、失败或取消；成果详情同步显示数字与进度条，历史接口每次返回前最多同步 4 条可见生成中任务。首次加载、可恢复的刷新失败、成果缺图、供应商不可用和客户方案加载失败均有明确状态；客户方案查询失败时会阻止继续生成，避免成果静默写入错误方案。
- 工作流协同：显式 `workflowId` 会直接续接；未显式选择时，同一客户/户型只有一个活动方案则自动复用，存在多个方案则拒绝静默合并并要求客户端选择，也可明确新建备选方案。任务映射为 `base_render`、`perspective_upgrade` 或 `soft_furnishing` 阶段；基准/软装阶段首个成功成果自动采用，后续同阶段成果只作为候选。小程序防重按方案、阶段、正式户型、目标范围和房间共同判断，因此厨房与客厅可并行，但同一厨房不会重复冻结点数；其他员工的同目标活动任务只返回忙碌状态，不暴露其任务跳转。自动续接传递 `sourceResultTaskId`，服务端在冻结点数前重新校验同方案、同目标和户型时效，将内部成果复制或把外部供应商 URL 下载固化为新的 `ai_generation_input`，并写入 `parentGenerationId`；它与手动空间上传互斥。历史“再设计”继续复用原始输入，缺少精确目标的旧任务只允许显式查看/再设计。换风格/软装可在小程序继续，提案/灯光提示到后台深化。无客户上下文时仍可作为独立快速任务运行。
- 视觉：成功态使用本地渲染的 Lucide 操作图标和极细分隔线，成果/对比容器跟随服务端输出比例，参考复刻以参考图作为对比源，并以 iPhone 13 Pro `390x844` 为基准调整布局。场景或真实户型保持为首屏主视觉，方案内容层叠在其下方，不再把空间压缩成普通横幅。首页以 `design-references/ai-design/ai-design-immersive-c-floor-map-v1.png` 为主体方向，吸收 `design-references/ai-design/ai-design-immersive-b-workflow-v1.png` 的方案阶段与“下一步”，未关联户型时使用 `design-references/ai-design/ai-design-immersive-a-space-tour-v1.png`；选择户型后，全屋/房间目标使用参考图中的上浮底部面板、紧凑绿色选中标签和短下划线，方案阶段明确区分已完成勾选节点、带“进行中”标记的双环当前节点和虚线待进行连接，方案摘要与下一步操作保持为两个独立视觉层级，同时保留原有实时选择与生成行为。在宽度不超过 `360px` 的窄屏真机上，无户型推荐区仍保持紧凑的横向标题/操作层级，并在第四个空间锚点与正式户型选择卡之间保留安全距离，不继承其他页面状态的纵向堆叠按钮。成果页视觉基准仍为 `design-references/ai-design/ai-design-result-v2.png`，无户型室内图为生成式资产 `miniprogram/images/ai-design-hero-v3.jpg`。
- 正式户型：入口传递 `floorPlanId`、显式 `targetScope: whole_floor_plan | single_room`，仅单房间携带 `roomId`。后台通过正式墙图读适配层派生尺寸、层高、开口摘要和导航只读模型，不修改 `FloorPlan.layoutData`；完整户型生成额外派生 1024px 墙体/门窗控制图并作为独立 `MediaAsset` 通过图片编辑生成抬高等距视角、移除顶面的 3D 剖切概念图，单房间户型生成通过量房摘要调用图片生成。成功的导航封面仍属于 `AiGeneration`/`MediaAsset`，绝不写回正式户型；来源接口只附加派生导航模型和经过权限校验的签名预览数据。关联正式户型的参考复刻同样派生控制图；选择单房间时只绘制该闭合房间及其门窗，并将控制图放在参考图之前提交。来源选择器只返回当前企业角色可访问的正式户型和闭合房间（设计师按分配线索/归属户型、量房员按归属户型、企业负责人按企业范围）；仅凭户型数据生成的是概念效果，不是施工级或像素级还原。
- 有限支持：仅企业员工可用，依赖平台统一供应商路由和企业 AI 点数；服务端可在不改变小程序 API 的情况下路由到 GRS、Pollinations 或其他已配置兼容供应商。小程序场景始终使用平台配置的逻辑模型默认值，不向用户开放自由创作台的模型选择器或模型/分辨率价格控件。关联户型的复刻会同时发送量房控制图与参考图，冲突时以结构控制为准；二维墙图不包含实测相机位姿，供应商仍不保证对参考图进行像素级 1:1 复制。3D 导航封面的家具和未测量材质可能变化，过期后不会继续作为当前封面，也不能反向作为量房数据源。纯户型生成也无法推断未测量的材质和精确镜头。没有微信支付、局部遮罩替换或普通业主账户。媒体 URL 始终使用现有小程序鉴权资产接口：本地 Provider 直接输出图片字节，七牛私有 Bucket Provider 在不改变页面契约的情况下跳转到短期签名 URL。后台的七牛存储前缀只影响后续新上传的服务端对象 key，小程序页面和资产 URL 无感。默认情况下 GRS `http(s)` 结果图直接返回上游 URL，正式环境需将其主机加入微信小程序下载合法域名；当平台启用七牛转存后，只有后续结果改走七牛签名读取路径。七牛上传失败不会回退本地，历史资产继续按自身稳定配置读取，HTTPS 下载域名必须加入微信小程序合法域名。生产本地存储必须配置共享 `AI_ASSET_STORAGE_DIR`，小程序签名媒体地址还需要 HTTPS `MINIPROGRAM_API_PUBLIC_ORIGIN`。

## 正式量房

- 页面：`pages/surveying-editor/surveying-editor`；所有入口由 `utils/surveyNavigation.js` 传递 `leadId` 和/或 `floorPlanId`。
- 数据合同：`FloorPlan.layoutData` 只能是 `{ version: 4, measurementMode: 'surveying', surveyGraph }`，墙图单位为毫米。
- 已实现编辑行为：启动恢复、本地/云端草稿、直墙和斜墙预览/确认、BLE/手输墙长、复尺、共享墙闭合、提示性闭合候选，以及从待确认斜线预览直接闭合（“合”会先按当前预览长度落墙再闭合）、门窗、开口尺寸/开向、在已有顶点、墙体内边、墙体外边或画布空白处放置墙链光标，以及随首墙移动并在边界限位的独立墙链第一面确认墙内/外测量边提示；吸附到已有墙体或顶点的续画墙链继承既有边界，不显示该提示；内边顶点优先于邻近内边线，但更近的外边不会被内边顶点覆盖；闭合房间的墙体外壳及外侧转角由闭合边界推导，不受所选测量边影响；撤销/重画、完成提交和测量审计队列/补写。
- 已实现测角：斜线方向阈值吸附、数字面板输入、操作员确认的手机姿态角度，以及三次 BLE 三角边长读数和余弦定理校验。关闭面板不改墙体几何，也不遗留姿态监听。手机姿态和勾股测量复用同一固定壳层测角浮层：手机模式提供水平圆盘、一位小数实时角度、基准设置和手输回退；勾股模式提供带编号的 A/B/D 毫米读数、测量中/已完成反馈、校验错误、重测和一位小数计算结果。测角浮层打开期间临时隐藏原生画布层的撤销/重画、拖放光标和拖拽放大镜控件，关闭后按原状态恢复。
- 已实现绘制/编辑：覆盖完整墙厚和开口宽度的 CAD 风格门窗符号、未闭合内测边红线、房间填充仅接受首墙正向或反向能够完整闭合的墙链、单侧墙体与连接节点补面先做全局实体合并再统一填充和描边（连接节点、L/T 型接入和重合分段不再出现内部端帽、斜缝或独立方框），闭合户型使用工程图式外轮廓 `DimensionPlan`（空间边界先做几何拆分和重合边抵消，不同 ID/不同分段的共享墙与封闭内部孔洞都不标注；连续多墙或含门洞的外边界使用靠墙的定位分段链；上、下、左、右等每个外侧方向仅有一条跨整套户型外包范围的全局总尺寸，不再为局部 run 重复生成总尺寸；窗户保留 CAD 图形但不生成重复细分尺寸；细延伸线从渲染后的外墙面起笔，尺寸线端点随外墙面和斜接外墙转角定位，再推送至整套闭合户型外轮廓之外的全局尺寸带，并使用小箭头和文字断线）、画布、拖拽层和底部拖放控件统一的细线十字/方框光标；拖动光标时左上角放大镜复用正式 Canvas 场景渲染器，局部墙体实体、转角、选中态和门窗符号与主画布一致，不再使用独立线段近似，并明确显示“顶点吸附”“内边吸附”“外边吸附”或“自由放置”；以及会避开墙体和固定控件、统一使用绿色底面的画布锚定操作提示；构件规格、构件 BLE 测距、翻转/模型面板，以及选中门窗的 Three.js 预览。画布平移和双指缩放使用按动画帧合并的临时轻量渲染层：手势期间保留墙体、房间填充、轮廓和门窗，临时隐藏尺寸、房间名称、辅助线和操作提示；手势结束后只重建一次完整正式场景。高频手势帧不更新页面数据，也不重复计算墙体实体并集和尺寸计划。
- `miniprogram/utils/surveyDimensionPlan.js` 与 `miniprogram/utils/surveyWallSolidPlan.js` 是两端无渲染依赖的算法源；后台开发和生产构建前同步本地镜像，不再通过扩大 Turbopack 监控根目录来跨仓库加载。

## 维护规则

修改小程序页面、组件、工具、API 流程或数据合同前，必须先阅读根目录指令、本清单以及对应的设计或正式量房文档。完成后必须在同一次修改中同步本文件和英文镜像，记录真实入口、API、角色/条件、数据合同、状态和限制。正式量房规则必须与 v4 墙图合同一致；不得把 mock 或规划控件写成在线功能。如果确实没有功能文档影响，必须在交接说明中明确写出。
