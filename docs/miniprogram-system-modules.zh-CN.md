# 小程序当前功能清单

### PostgreSQL-only AI API（2026-08-05）

小程序 AI 媒体、任务、工作流和能力接口只接受 PostgreSQL bigint 标识。客户端不再依赖 MongoDB 或 ObjectId 兼容层；提示词库和七牛云媒体配置通过 PostgreSQL repository 与存储适配器提供。

> 2026-08-03 PostgreSQL 迁移更新：`app.js` 加载企业品牌时调用的 `/api/branding/[id]` 已改由 PostgreSQL 企业资料提供，客户端请求路径和品牌字段契约不变。

本文档记录 `miniprogram/` 原生微信小程序的当前实现。事实基线是当前
`app.json`、页面处理器、共享工具和实际调用的后台 API。

> 2026-08-04 PostgreSQL migration update: Mini Program AI upload, formal-plan source, task lifecycle, and workflow-list routes now use tenant-RLS PostgreSQL bigint assets and generations; historical ObjectId asset URLs remain read-only through the compatibility delivery branch.

## 状态与运行环境

- `Implemented`（已实现）：页面及其真实数据/操作链路可用。
- `Limited`（有限支持）：依赖登录、企业角色、蓝牙硬件、供应商或特定正式墙图形态。
- `Placeholder`（占位/未开放）：只有 mock/本地行为、规划 toast 或没有真实服务端操作。
- 运行环境：原生微信小程序；`utils/api.js` 通过 JWT Bearer 请求；`threejs-miniprogram` 用于 3D 预览；可选蓝牙激光测距仪。
- 源码包保护：`project.config.json` 会从预览/上传包中排除测试夹具、本地开发日志和设计工具元数据；运行所需的页面、素材、工具及 `miniprogram_npm` 依赖仍会打包，以保持在微信 4 MB 源码限制内。
- 主 Tab：首页 `index`、客户线索 `leads-management`、设计 `ai-design`、我的 `mine`，另有自定义中置量房操作。只有这四个 `app.json.tabBar` 路由挂载共享自定义 TabBar；登录、详情、工作流、灵感库、推荐、正式量房及其他二三级页面不得渲染本地或重复 TabBar。共享 `128rpx` 内容区确保中置“量房”文字完全位于底部安全区之上；先保留 `constant(safe-area-inset-bottom)` 兼容旧版 iOS WebView，再使用现代 `env()` 声明。
- 共享 TabBar V3 还原（2026-08-07）：经确认的量房入口使用手持激光测距仪的完整透明小 K，
  不再添加圆形背景、圆形描边或圆形投影。企业员工使用五项版，角色尺寸为 `128rpx` 并向上凸起
  `30rpx`；未开放 AI 设计的地推人员使用四项等分真实入口，小 K 缩为 `112rpx` 并向上凸起
  `24rpx`，不保留空槽或显示禁用“设计”。独立原生“量房”标签保持既有 `96rpx` 安全基线。
  页面路由、最近户型查询、正式量房入口、
  API、认证和权限边界均不改变。TabBar、素材体积、访问可见性和离线调试针对性测试通过，小程序
  全量测试通过 `181/181`；用户现有微信开发者工具已在 `390x844` 基准核验地推人员四项版首页，
  证据位于
  `design-references/qa/v3-tabbar-promoter-four-item-home-390x844.png`；此前企业五项版首页、线索和
  我的的证据继续保留在
  `design-references/qa/v3-tabbar-no-circle-390x844-contact-sheet.png`。

## 分包与体积预算

- 主包只保留首页、客户线索、设计、我的四个 Tab 及其共享运行时；`packages/surveying` 承载正式量房编辑器、专属渲染/引导资源与本地 `threejs-miniprogram` 适配器，`packages/ai-workflow` 承载 AI 创建、结果、历史与兼容跳转，`packages/business` 承载登录和低频业务流程。
- 三个分包均为普通分包，只可依赖主包，彼此不得引用；不配置启动预下载。生产资源保持本地，主包预算为 `<= 1.5 MB`、各分包 `< 2 MB`，以微信开发者工具代码依赖分析为最终验收。
## 身份与共享上下文

- `/packages/business/login/login`：通过 `/api/auth/miniprogram` 支持微信手机号快捷登录和账号密码登录，将 JWT/用户信息恢复到本地。
- 会话切换：每个一级 Tab 页面在显示时都会要求共享自定义 TabBar 重新计算当前选中项和企业专属入口可见性；“我的”页在工作台响应补全当前用户上下文后还会再次刷新。因此从独立地推账号切换到企业设计师账号后，无需重启小程序即可显示“设计”Tab；退出登录也会立即重新应用同一可见性规则。“设计”不可用时，TabBar 直接渲染“首页 / 线索 / 量房 / 我的”四个等分真实入口并采用紧凑量房形态，不保留空槽，也不暴露禁用的 AI 入口。该调整仅作用于客户端表现层，不改变认证、路由、API 或 `enterpriseId` 权限边界。
- 登录页视觉：已按 iPhone 13 Pro `390x844` 基准实现
  `design-references/all-pages-ip-v1/06-login.png`。页面使用从参考图派生的本地小 K/F3 入户场景，
  保留已确认的品牌与欢迎锁定画面，并叠加双模式登录面板、本地授权图标、紧凑能力摘要和同屏返回入口；登录行为、
  加载/失败反馈、通知授权与页面返回语义保持不变。
- 访问仅限员工：账号密码登录必须匹配启用中的后台 `AdminUser`；微信 code/手机号登录必须通过已绑定 OpenID 或后台手机号匹配启用中的 `AdminUser`。未匹配的外部用户会收到 `403`，无法建立小程序已登录业务会话。账号、绑定身份、企业和权限解析已切换 PostgreSQL，并在刷新和请求上下文解析时复核启用状态。
- `app.js`：恢复会话，解析二维码 `enterpriseId`/`staffId` 推荐参数，同步员工专业上下文、企业品牌，并对已记忆设备尝试静默 BLE 重连。
- `utils/api.js`：携带 Bearer token，通过显式 `ACTIVE_API_ENVIRONMENT`（`local` 或 `production`）选择唯一 API 地址，401 时清理会话并提示重新登录。请求不会跨环境回退，也不读取持久化 `apiBaseUrl`。
- 小程序 AI 素材交付：`/api/miniprogram/ai/assets/[id]/image` 对新的十进制 PostgreSQL 素材 ID 在租户 RLS 范围内读取；旧 MongoDB ObjectId URL 仅保留给历史 AI 记录只读访问。
- 状态：PostgreSQL 登录与上下文恢复为 `Implemented`；具体路径仍依赖有效微信授权、账号、API 地址和企业/供应商配置。Phase 3 期间为 `Limited`：仍由 MongoDB 支撑的 AI 生成/媒体与订单/提成工作流域要等计划内 PostgreSQL 切换后才兼容 bigint 身份；线索、正式户型、测量和设备绑定现已使用 PostgreSQL。
- 设备授权：`/api/devices/verify-binding` 在平台范围查询已发现设备，但仅授权状态为 `assigned` 且与当前员工或企业匹配的设备。在 `/devices` 指派持有人会将闲置设备自动改为 `assigned`；`maintenance`、`lost` 始终不能被授权。

## 页面清单

### 首页与量房入口

- 页面：`pages/index/index`。
- API：`/api/miniprogram/home`、`/api/floorplans`、户型 POST/PUT、`/api/leads/[id]`、`/api/location/reverse`、`/api/users/me`。
- 已实现：首页统计、定位/城市、按角色过滤的最近云端户型（本地草稿存在时仍显示，且可直接进入正式量房编辑器）、留资弹窗、BLE 连接状态、记忆设备自动连接、新建/继续正式量房、房间进入、企业员工常驻 AI 设计快捷入口，以及首页直达客户线索和 BLE 配对的快捷入口。
- 有限支持/仅调试：底部中置“测距”入口会先请求最近一条 `/api/floorplans` 记录，再打开正式量房编辑器。将 `miniprogram/utils/debugConfig.js` 中的 `ENABLE_OFFLINE_SURVEY_ENTRY_DEBUG` 改为 `true` 后，接口请求失败会以 `startNewSurvey: true` 直接打开本地新建量房会话，可在后端不可达时调试编辑器样式和交互；开关默认是 `false`，保存仍要求正常的鉴权接口。
- 数据边界：线索、正式户型、测量、已分配设备的统计和最近正式户型均来自 PostgreSQL RLS Repository。AI 生成域尚未迁移，因此 `aiGeneratedCases` 明确返回 `0`。最近户型项还会返回其真实关联线索可用的 `customerName` 和 `communityName`；首页的提醒、进行中量房卡和项目进度卡统一消费正式户型只读 `display`：小区为主标题，“客户 · 第 N 次量房”为次级身份，持久化户型名称仅作兼容回退，状态、闭合空间数和时间仍为元数据。按角色过滤的 AI 来源接口也返回同一读模型。
- 权限边界：首页点击最近户型时，详情接口与最近户型列表使用相同的员工归属范围；企业管理员仍按企业范围访问，不属于企业的地推账号按自身 `staffId` 访问，普通员工不会因此获得其他员工户型的访问权限。
- 有限支持：写入/通知特征值的配对由硬件决定。BLE 调试日志会记录枚举到的通道属性、每一次命令写入及每一条带完整 Service/Characteristic UUID 的原始通知；接收缓冲区按通知通道隔离。厂商私有二进制回包仅保留为原始调试信息，确认协议映射前不赋予业务字段含义。
- 视觉基准：以 `design-references/all-pages-ip-v1/01-home-v2.png` 的 iPhone 13 Pro `390x844` 画面为首页基准。交付界面使用 F1/F3 空间服务向导首屏、上浮的正式量房卡、三张快捷服务卡和项目进度卡；本地派生场景素材为 `images/home-ip-v1/hero-scene-wechat-safe-overscan.png`，并为微信原生胶囊预留安全区。实时城市控件位于品牌锁定组右侧，标题使用“让小K陪你 / 把空间一步步 / 变成家”三行构图；Hero 固定为单一 `516rpx` 锚点，不再保留右上角“今日提醒”对话气泡或依赖微信胶囊位置的提醒定位。存在最近户型时，仅在中间正式量房卡内、位于小 K 完成/协助文案之前显示带铃铛图标的绿色圆角“今日提醒”标签。城市、统计、设备状态、最近户型、空状态和全部导航仍由真实数据及角色边界驱动。
- 占位：帮助中心仍显示“即将上线”消息。

## 测绘引导 Canvas 实现说明（2026-08-05）

底部光标和测距目标采用专用末端布局：按真实控制坞几何上移对话框，优先把小 K 放在卡片下方，并用直线虚线直接终止在按钮正上方；按钮内部的绿色原生描边和顶部菱形继续负责高层高亮，按钮触摸树不变。空间闭合后的等待拖放和光标拖动状态会同步清空、隐藏旧的顶部原生测量浮层，禁止在左上角留下无文字的白色矩形。下一墙链光标放置后，当前测量段只从 `activeSpaceStartWallIndex` 及其后的新墙中解析；尚未拉出新墙时不得复用上一闭合房间的末墙，也不得额外绘制第二组蓝色十字辅助线或恢复旧量测浮层。

正式量房引导是已实现的本地表现层。白底对话框、浅绿箭头尾巴、水平居中的“小K提示”标签、小K图片、目标光圈、绿色虚线贝塞尔弧线和箭头均由主 `survey-canvas` 绘制，不再使用 WXML `cover-view` 覆盖节点，因此不会截获画布拖动、平移或双指缩放手势。顶部持久化“引导”开关仍是唯一控制入口；该视觉层不改变 API、角色边界、v4 墙图、草稿或测量审计合同。

引导正文必须以当前 Canvas 字体和卡片实际内宽通过 `CanvasRenderingContext2D.measureText()` 换行，禁止仅按字数截行导致中文越出气泡。旧的 WXML 测量气泡不保留 `wx:else` 回退分支；没有顶部测量值时不得出现空白白色浮卡。

对话框尾巴使用连续 Canvas 轮廓：填充部分压入卡片边缘，仅描绘两条外露斜边，并按卡片同比例缩放，禁止拼接三角形。小K左右指向在每一种引导状态都按真实目标的水平几何关系推导，包括测量边状态；卡片高度需在最后一行测量正文后保留明确的底部内边距。

卡片、小 K 与连接线统一进入一次避障求解。卡片和完整角色必须保持间距且位于安全工作区；尺寸文字、房间信息和固定控件是不可覆盖、不可穿线的硬障碍，墙体、门窗、尺寸线与红色测量边按权重避让。连接线先对多条贝塞尔曲线采样，无法绕开硬障碍时改用平滑网格路径，仍无安全路径时省略本帧连接线；小幅平移优先复用上一有效布局以避免跳位。指向底部光标或测距按钮时，目标使用控制坞真实几何，按钮内部的原生描边标记显示高层高亮，事件继续冒泡给原按钮。旧的纯绿色背景说明气泡已删除，白底小 K 对话框是唯一教学说明；测量边切换与“可闭合”操作仍保留。

- 闭合房间角点续测修正（2026-08-07）：从已闭合房间的角点重新起画直墙时，即使两个角点都已有两条边连接，也允许沿既有共享边路径寻找相邻房间的闭合目标。第一或第二条新测墙会保留矩形补全参考，手输/BLE 确认长度后会重新应用正交吸附，避免确认读数重算端点后丢失吸附。该修正恢复真实 `merge` 闭合提示，不改变页面路由、API、角色边界、毫米/v4 墙图合同或测量审计行为。
- 闭合墙删除后的续测恢复（2026-08-07）：从已闭合相邻房间删除墙体时会清除旧的光标/墙体吸附记录，避免“重置光标”恢复到已删除墙或上一房间节点。重新吸附剩余端点后，缺失墙会再次显示正交辅助和非空共享边闭合候选。

## 测量员—设计师获客流程（已实现）

专项业务与数据契约见 [`docs/measurer-designer-acquisition.zh-CN.md`](measurer-designer-acquisition.zh-CN.md)，英文镜像为 `docs/measurer-designer-acquisition.md`。

- `packages/business/acquisition-center/acquisition-center` 是设计师确认客户已添加微信的唯一入口。它通过 `/api/acquisition-tasks` 提供按角色裁剪的待确认/已完成任务、汇总、分页、失败重试、幂等确认和通知 `leadId` 精确定位；测量员响应只在页面级返回一次当前绑定 `designerProfile`，汇总后显示唯一“我的设计师 / 查看微信”入口，客户任务卡不重复显示设计师联系方式。确认只写 `acquiredAt/acquiredBy` 并生成获客提成，不修改客户主流程状态。任务列表支持原生 `scroll-view` 手动下拉刷新；页面可见时每 30 秒刷新当前状态，页面隐藏或卸载时停止定时器，且不会与已有请求并发。
- `pages/leads-management/leads-management` 与 `components/lead-list` 使用四阶段客户主流程，不再提供“已获客”筛选。测量员在胶囊安全区下方通过“我的设计师”打开共享 `designer-contact-sheet`；列表卡不再重复铺设微信号和二维码。
- `packages/business/lead-detail/lead-detail` 同时接受普通 `id` 和通知深链 `leadId`，显示四阶段状态时间线、下一步提示和普通信息组中的获客事实，不再承载获客确认主按钮。正式量房卡只显示真实墙图状态、闭合空间数和更新时间，缺少正式户型时明确提示“从墙图开始建立客户户型”；绑定设计师仍通过共享底部名片查看。
- `packages/business/commission-records/commission-records` 通过 `/api/commission-records` 读取独立获客提成；测量员看到待结算/已发放汇总，salesperson 原有订单提成保持兼容。
- “我的”页面从 `/api/miniprogram/mine` 获取按角色裁剪的“获客协作”入口和真实待办角标；站内通知通过 `/api/miniprogram/notifications/read` 标记已读，并按 `metadata.page` 优先深链到协作中心的对应记录。微信发送失败由站内通知兜底。
