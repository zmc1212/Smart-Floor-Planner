This file records the current Admin UI rules and the latest state of routes
that have an approved refactor direction. It is not a chronological migration
log. Git history contains earlier refactor attempts.

## Shared contract

- Next.js App Router pages use the established Ant Design 5 and Ant Design Pro
  system, including the shared `AdminAntdProvider` token configuration.
- Use `PageContainer`, `ProTable`, Ant Design form/feedback primitives, and
  established Admin business components where they fit the workflow. Do not
  introduce a parallel UI system for new Admin work.
- Page frames keep a 20px stack gap between sibling sections, wrap page-header
  extras instead of compressing titles, and keep table/filter/action labels on
  one line. Buttons that render as links (or sit inside `Link`) keep their
  intended text color so primary green and danger surfaces stay readable.
- Business pages preserve route, API, tenant, role, and mutation boundaries.
- Administrators (`admin`, `super_admin`) inherit enterprise-owner business
  management permissions within the selected enterprise. Shared role gates use
  `isEnterpriseManagementRole`; verify all three roles. Tenant, source/participant,
  consent, lifecycle and sensitive-password checks continue to apply.
- Shared Admin controls belong in `admin/src/components/admin/*` or the
  established business-component area.
- Visible mutations use the shared success/failure operation feedback UI.
- Use `http://localhost:3006` for visual checks. Authenticated checks use the
  user's existing Chrome session.

## Handoff

`/login`, `/floorplans/kujiale`, the AI Studio cluster (`create` / `scenarios`, the `/ai-studio/floor-plan/[id]` generation detail, and shared creation/workbench dialogs), `FloorPlanViewer`, and the Admin `Sidebar` shell now use Ant Design 5 controls. The four legacy tool entries are server redirects into `scenarios`, and heavy AI workspaces/dialogs load on demand via `next/dynamic`. An `(admin)/error.tsx` boundary renders Ant Design retry feedback for route failures. Dark studio shells keep their night theme via `ConfigProvider` + `studio-antd-theme`. Root layout mounts client `AntdReact19Patch` (`@ant-design/v5-patch-for-react-19`) so Ant Design 5 wave effects and static methods work on React 19. Root `AntdRegistry` enables css-in-js `layer` with `@layer theme, base, antd, components, utilities` so Tailwind utilities override Ant Design's global `a { color: colorLink }` (inactive sidebar items stay muted gray; only the active route uses primary green). Unlayered `a.ant-btn*` / `a .ant-btn*` color rules restore intended button contrast when those links still win. Shared `notify`, `ConfirmDialogProvider`/`useConfirmDialog` (antd `App.useApp().modal.confirm` under `AdminAntdProvider`'s `ConfigProvider` + `App`), `AccountSettingsProvider`/`useAccountSettings` (sidebar avatar account menu with login/sensitive-password modals), and `ImageUploadField` live under `admin/src/components/admin/*`. The former `@/components/ui` parallel kit, unused AI helpers (`AiQuotaBar`, `ChatInterface`, `ImageCropperDialog`, `RechargeDialog`, `ai-tool-frame`, `workflow-runner`) and dead components (`UserDashboard`, `DepartmentTree`, `EnterprisePageHeader`, `enterprise-utils`) were removed. No route/API/permission or admin module-inventory behaviour change.

When a refactor changes visible behavior, update the route's single current
record and both language files. When it changes only implementation without a
route/API/permission or visual impact, state that in the handoff instead of
adding a new ledger entry.

Current AI workbench composer behavior: `/ai-studio/scenarios` exposes an explicit
`整屋户型` / `单间现场` render-mode selector. Whole-plan mode attaches the formal
floor-plan control reference and keeps the scope picker; single-room-photo mode
does not upload the control image and treats uploaded site photos as the camera
authority. In single-room-photo mode, `客户现场图` opens a multi-select gallery
from the current lead's persisted `lead_site_photos`; temporary upload remains
available. The batch submits explicit `styleReferenceAssetId` and
`sitePhotoAssetIds`; a template cover never satisfies the required site-photo
role, and both client and server block single-room-photo generation until at
least one gallery-selected or computer-uploaded site photo exists. Reference
thumbnails are labeled by role (`户型结构`, `风格图`, `现场图`).
The round gallery also renders every persisted `referenceAssetIds` item on each
batch card, including the control image and supplemental references, so Admin
and Mini Program show the same complete reference set.
