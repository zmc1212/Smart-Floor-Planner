# S4-B：整数网格 Snap Rounding

状态：正式整数毫米墙图的 **Implemented** 能力，替代 P0 的非整数交点拒绝。不包含 S4-C 独立墙、S4-D 内洞/嵌套空间或 S4-A/S4-E 真机验收。

## 算法与事务

- `miniprogram/packages/surveying/utils/survey/geometry/snap-rounding.js` 在修改任何墙体前，基于全部原始墙端点和严格交点生成纯计划。交点使用精确有理数舍入，包含负数半网格边界；安全整数行列式走快速路径，大数值走精确计算。单位热像素拥有 `[x−0.5,x+0.5) × [y−0.5,y+0.5)`；恰好半格向正无穷舍入，因此半格边界不承诺镜像/旋转不变性。墙数组和端点顺序变化、整数平移保持确定结果。
- 所有穿过热像素的原始线段都经过像素中心，包括未经过原交点的第三条墙。相同像素共享一个节点。顶点沿原墙主轴排序，次轴处理角点平手；原始整数端点保持固定。
- 首次弯折后，基于同一像素集合执行单调、有限的补充节点化，处理弯折线段新进入的像素，避免后续提交再次改变已接受图。该稳定化扩展首次 Snap Rounding；不是两两独立舍入或 UI 容差吸附。每条原墙最多加入与 arrangement 像素数量相同的顶点。当前采用两两求交和像素扫描，不宣称扫描线复杂度或低端真机耗时。
- `operations/node-intersections.js` 在既有隔离提交事务内执行计划。`wall-split.js` 接受有序拓扑切点，跳过交互拆墙的 1mm 去重，保留不同像素间的 1mm 短段。首段保留原墙 ID，源墙 ID 和 Space 引用继续传递，会话节点别名及活动墙链索引重映射；Face/Space 同步和 full 校验决定是否提交。
- 热像素定义遵循 [JTS SnapRoundingNoder](https://locationtech.github.io/jts/javadoc/org/locationtech/jts/noding/snapround/SnapRoundingNoder.html) 的全 arrangement 原则。代码为本地实现，未引入 JTS 运行依赖。内部精确运算使用 JavaScript `BigInt` 内建能力，持久化不包含 BigInt、有理数、像素缓存或派生路径。

## 测量、门窗与拒绝边界

共享拆墙器保持原始读数总和，按段分摊并保持 `lengthMm = rawMeasuredLengthMm + closureAdjustmentMm`。弯折及逐段整数长度可能使有效长度总和不同于原直墙；差值体现于既有平差字段，不虚构额外原始读数。单源墙有效变化超出 2% 且夹在 25–150mm 的共享预算，或事务变化总量超过 1,000mm，返回 `MEASUREMENT_ADJUSTMENT_BUDGET_EXCEEDED`。

门窗切点沿用实体占用保护。在任何拆墙前，从完整计划收集所有入射墙厚，400mm 交叉墙不会因在数组中靠后而漏掉净距检查；距端点 1mm 以内的拓扑切点同样检查。安全门窗沿用迁移器保留宽度及宿主墙相对位置；弯折宿主可能产生网格精度的世界坐标变化，原精确共线拆墙仍保留世界坐标。跨段开口继续不支持，返回 `OPENING_SPLIT_CONFLICT`。

原始正长度重叠返回 `OVERLAPPING_WALLS`；舍入后重复物理段、非法墙体实体、退化房间及嵌套空间仍由共享校验器拒绝。几何量化不授权猜测物理墙归属或新增房间语义。拒绝不改变输入图、会话和撤销/重做快照；服务端写入和恢复验证提交图，不暗中运行修复。

路由、API、角色、租户边界及 v4 `layoutData` 外壳不变。未修改 WXML、样式、插画、交互控件或 BLE 协议，不需要新增 UI 设计或恢复台账条目。Canvas/宿主运行 QA 仍按 S4-E 等待用户手动截图，未自动操作微信开发者工具。
