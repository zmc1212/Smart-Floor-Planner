# 小K集成模块合同

| 入口和所有者 | 合同 |

| Construction | 项目、授权成员、有效计划、报告原始记录、精确版本方案、整改与复核由同一 Construction 服务及其事件投影维护。客户决定方案版本，工人提交获权现场原件，项目管理者核实并授权回传。四端依原角色读取获权视图。日周报读取相应周期的同源记录，每企业每周只领取一个调度槽并生成四个角色投递。 |

| Delegation / Outbox | `native_workflow_delegations` 是委托主记录，保留 `state` 和复核等待对象等兼容字段。房间水电和单事项复核共用 `native.delegation.v1`、企业串行顺序、租约和审计。每个事件可影响多条委托，各自按委托 ID 与事件 ID 记录。委托进展、原会话消息、事件处理结果与执行完成在同一事务写入。 |
| Conversation / Message | 原私有咨询保留消息序号、来源和身份。公开上下文绑定具体公开版本，公私切换时按当前来源与项目权限重建模型上下文。相同原话重放及同范围的进行中复核按原咨询去重。获权业务结果通过稳定的 Outbox 键回传原会话，读取和重试校验当前参与人、来源与业务版本。委托状态回执从原指令与本咨询当前获权委托重投影，方案和关闭回执从对应 Construction 事件重投影。 |

公开网页候选的标题、域名和来源类别仅供选择。原生 Responses 提取回执的摘要按其来源地址绑定，引用目录只接受核读原文。C01 完整历史、引用打开和 LangGraph 祖先来源复用先鉴权，再核对保存原件和当前源站。页面变化、撤回、访问被拒和暂不可读沿原来源反馈，响应附可用的具体 `errorCode`。轮询增量沿已存快照投影，完整刷新复核当前公开来源。公开来源说明对应文件的内容及已核实的适用时间。企业标准、获权现场记录和正式业务结果各自有独立来源。现行规范完整性见[集成验收](xiaok-integration-audit.md#i610-防水专业-agent-可信度与现场资料limited)。

I6.15 补充：Native Executor 和 LangGraph 共用 `start_delegation` 输入、授权、幂等和正式委托入口。单独授权的用户消息在登记事务提交后可用站内回执结束，取消沿原会话控制；模型首稿、工具操作和服务回执分别留存。专业登记事务同时保存首个 Outbox 事件与正式 Run，固定原 C01、客户、项目、房间、原消息和已发布 revision/digest。Construction 初始事项事件保存相同来源和 Evidence 引用，后续变更保留该来源。复核结果在明确披露范围内回复原 C01 消息，受保护的原件读回继续重验当前授权。`long-term` 与员工项目投影分别经原权限读取关联身份；历史事项沿原审计记录读取。[运行与验收](xiaok-waterproof-workflow.md)。

托管混合检索在授权后预检专用配置。缺配置返回 `retrieval_unavailable` 并记录原因；关闭知识、未命中和未配置各自保留状态。现有委托工艺核对使用同一检索与版本约束，核对回执按当前知识 epoch 及项目上下文失效，由后续获权事件重新读取。工艺引用和业务完成回执各自保留，施工结论由 Construction 服务写入。

公开 PDF 沿原 `read_web` 及 `web_fetch` 运行。后者只接受用户原话、已发现候选或已成功读到的网页附件链接。默认整件 4 MiB。超过整件上限的 HTTPS PDF 只在已知总长不超过 8 MiB、有强 ETag、服务端支持字节范围时读取，最多四段，每段至多 2 MiB，共用下载时限和原重定向、DNS 固定、TLS 边界。解析沿独立 pypdf 子进程。私有运行检查点保存原件、原始与最终 URL、原件 SHA-256、逐页状态及错误。页定位进入现有 Evidence，引用文字从同页原文解析，重进复核原件及页正文。上下文超限时只选完整相关页。扫描图或仅有重复水印时返回 `pdf_ocr_required`。企业 DOCX/PDF 的上传、解析及审核继续走原知识服务。

防水标准沿用已对照原件的六页摘录。给排水标准经原图核对后新增实际第 12、24、25 页的有限摘录，其余扫描页待人工核对。每份摘录绑定官方源站、路径、字节 SHA-256、实际页和文本指纹。C01 首读沿公告的实际附件，并核对同编号同版的状态目录。重进和引用打开先核对保存的原件及页文，再以同一 URL、强 ETag 和长度校验当前源站；老回执无强校验器时重新读取字节核对 SHA-256。有已核摘录的官方附件同时复核原公告链接。下载超时或 Reader 故障只影响本次读回，源恢复后可重开。撤回、替换或当前访问被拒时，私有存档不能放行。

发布公告只证明其公布、实施和明确列出的废止条文，标准正文只证明该版条文和其写明的适用范围，现行或废止断言需要同版状态原文。状态未核实为 `unknown`，相反依据并存时阻止把其中一方说成确定结论。目录及原文均不能确认具体旧房的现场做法或工序放行。企业资料由原 KnowledgeRetriever 提供并按企业、项目、受众、成员及有效版本核对。第 18 页 PPT 仅支持团队安排防水施工和后续检查。具体管根、涂刷高度、闭水时长和铺砖条件无企业条款。项目实况仍由当前获权 Construction 读回，普通解释无委托。实模协议和仍待验的场景见[百炼适配说明](bailian-responses-adapter.md#15-i67-起的实模开发与验收)及[集成验收](xiaok-integration-audit.md#i67-专业规范证据链limited)。

新准入的本人房屋文字咨询，在未索取档案时也能通过原 `query_business` 查询唯一在施工项目。服务端从会话绑定房屋，只开放施工域。无房间时返回实际节点和团队进度说明；指定房间时按当前项目精确房间核对，只补已向该业主发布的记录。无唯一项目、无唯一房间或无记录时说明本次查询范围。重进沿原业务快照复验，工地权限或记录版本失效时隐藏派生旧答。档案、正式图纸、到场联系及现场决策继续各走既有入口。公开围观不开放此读取。企业 RAG 省略 `scope` 时仍按原受众查询有效的企业通用和当前项目资料。

### I6.10 防水专业咨询与执行

`waterproof-specialist` 通过既有 Assistant Worker 与网关运行。业主问工艺、企业标准、规范状态或本人房间进度时按当前意图和更正限定读取。终稿和同轮唯一修复共用段落来源及承诺校验。防水专业咨询的量数沿同段 Evidence 检查。原有一次修复可定位段落、数值、单位及同轮来源。最后一稿仍有无据量数时，只投递经校验的独立引文段，并说明本次无法确认具体参数。规范中的条件、引用释义和核对清单按同段已验证原文的约束对象核对，咨询的资料接收范围仅说明本轮输入。项目已施工、已验收或放行须有获权业务回执。已查规范的版本编号可用作文件标识，条款、页码、发布日期和施工量数各自需要适用的依据。技术回答只给相关标准页，现行性与实施日期另取目录和公告。公开状态上下文引用到公告或目录中已读的对应原句，原来源保持可核验。

`waterproof-inspection-v1` 绑定原咨询、业主、项目、房间、原消息及已发布的版本/摘要。Worker 复用原委托 Outbox 租约、PostgreSQL Runtime 检查点及 Durable Task。子 Assistant 作业沿原业主身份版本，等待照片及经理复核时释放模型。当前同房间获权待核对记录触发原 Construction 事项，经理明确回传后在原咨询投递。重进复核当事人、原记录和复核版本。新模板的三个出口对应检查清单、补资料和已观察事项。新定义保留原类型化端口，独立节点能力版本继续编译历史 Run。清单取原 Agent 终稿引用和服务端复核的版本，公开依据包含规范编号和实际 PDF 页。定义沿原文件 Store，业务状态沿 PostgreSQL Runtime、Durable Task、Outbox 与 Construction。平台真实运行读取使用会话租户及 Construction 项目权限。[完整节点合同](xiaok-waterproof-workflow.md)。

新定义的 Agent v3 节点只提交实际分析回执，独立 Evidence Assessment 节点验证当前选中引用、来源角色与施工记录，三路分支读服务端结果。企业空、企业检索故障、公开依据缺项分别记录。图片启用依赖原企业能力配置及精确北京百炼模型，照片用原上传和 Construction 发布权限与版本，读取撤回时派生文本一并失效。C01 沿用当前输入、引用、来源不可用和跟进界面。

### I6.11 专业决策语义与房间证据

回答中的验收表述统一分四类：A 标准规定（规范原文明确的条件）、B 专业解释（条文解释、适用范围和一般建议）、C 项目事实（本项目实际发生，须有当前获权施工记录）、D 正式业务结论（须有 Construction 正式回执）。同一段包含多类时逐条判断。A/B 只在引用对象、完成强度和适用范围都能由本答案实际选中的标准原文支持时成立；裸条件不能由完成式原文反向授权，完成式也不能由裸条件补成。项目主语、已/目前/现场/回执等断言继续拦截。该合同由 Agent 提示词、终稿校验和保存层共用，不另建事实库，不关闭承诺守卫。

房间只来自服务端 specialist binding。专业回答、`query_business`、`start_delegation` 和照片读取都按同一项目与精确房间执行；其他房间的已发布记录即使仍有效，也不能支撑本房间回答（`misattributed_project_room`）。同名房间跨项目、项目内重名房间、缺房间和无权限分别返回明确状态，不回退到整项目记录。历史原话只用于理解指代，重进仍复核来源版本、媒体权限和当前项目成员。

照片分析输出固定信封：可见现象、可能问题及理由、照片无法确认的内容、需补充的照片或资料、可对应标准、可信程度和人工复核标记。照片不得声明验收、放行或试验合格，不得给出精确施工量数；存在可能问题时必须人工复核并列出补充证据。真实工地照片必须来自隔离项目中获权的 Construction 原件并按原件 Hash、发布版本和当前权限复核；本轮无可用真实工地照片，真实工地验收为 `not_run`。

检查项绑定项目、房间、阶段、Agent 版本、Run、来源版本、来源类型、适用性、当前项目状态、检查状态和人工复核标记，并归入基层、管根、阴阳角、预埋、企业工艺、材料与记录、防水层、试验验收、保护、下一道工序十类。模型分析只能产生企业/公开/项目/建议/缺资料/不适用/待人工确认，不能产生已正式复核。来源撤回或项目房间变化时，旧清单按原 Run 版本保留，后续运行重新评估。[验收](xiaok-integration-audit.md#i611-防水专业决策可信度与真实工地验证limited)。

### 数据迁移与回退

使用 PostgreSQL 17。新库先由库 owner 预置 pgvector。通过 `cd admin` 后的 `npm run db:migrate` 应用迁移。入口在同一事务内锁定迁移、核对每条账本的时间戳与已知 hash、检查委托表形态和强制 RLS，再执行待应用 SQL。未知 hash、混合分支、重复时间戳、缺失前序和委托表与账本不符均停止升级。

空库和原 Native 路径依次执行 `0124 → 0125 → 0126 → 0127`。完整 Bailian 原路径执行 `0124 → 0125 → 0127`，由 `0127` 合流原表，允许同一来源消息下不同操作键的委托。已有 `0126` 的库仅执行 `0127`。水电委托按来源消息唯一，复核委托继续按企业、业主、操作键唯一。原账本行和原 SQL 保持原样，账本只记录实际执行的迁移。Bailian 原托管检索库的文本型 embedding 保留，切换到本地向量检索需要先完成向量数据迁移。

升版前保存源账本与可恢复快照，隔离验证应用角色、租户、触发器与原业务数据。升版窗口内停用历史 Worker，使用已核对的集成版本连接升级库。业务回退先停用相关企业开关及集成 Worker，保留现有记录与副作用回执。需要回退数据库时将快照恢复到独立库，核对升级后的新增业务和未知回执，再决定切换。按 [集成审查](xiaok-integration-audit.md) 核对具体迁移和生产验收边界。

### I6.12 照片结构化与第一版冻结

图像轮保持原 \conversation-images-v1\ 与 \inal_response\ \kind\/\	ext\，不扩大工具 Schema。服务端先解析正文七节固定文本；未解析时执行一次独立文本归一化调用（\jsonOutput\、同一 \AgentModelGateway\、同一 ailian/deepseek-v4.1-flash-1017、不重发图片），结果经 \parseSpecialistPhotoAnalysis\ 严格校验。Run 步骤 \gent_photo_analysis\ 记录解析结果；解析失败保留原正文并记 \ailed\，不伪装为结构化成功。用量、请求 ID、实际模型与失败原因沿原台账保存。

工作流三路径与四端读取同一 Construction 事实；正式事项、经理复核、C01 回传、撤权与重复事件继续沿用原合同。冻结标识、已交付/不支持能力和复制其他专业 Agent 的步骤见[第一版交付](xiaok-waterproof-agent-v1-release.md)。

### I6.13 解释修复与 PDF 页引用

知识解释的 `unsupported_model_commitment` / `standard_status_unverified` 修复反馈现精确到问项、段号、缺失数字/量数与同轮 citationId 候选；状态守卫把“现行状态/情况/结论/信息/记录”识别为话题标签，不当作现行断言。`advice` 段由服务端显示为“一般建议”，语义复核据此承认一般专业解释。PDF 页引用 `w:99:1` 经 Stable 会话 `70` 点击与退出重进验证，原件与页 Hash 保持；Reader 超时与撤回分别返回 `source_unreadable` / `source_withdrawn`。施工端 Stable 提交、业主 Stable 再切换授权本轮 `not_run`，未以服务端通过代替 UI 通过。
