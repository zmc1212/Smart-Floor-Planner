# 小K集成模块合同

| 入口和所有者 | 合同 |
| --- | --- |
| Assistant / AgentModelGateway | `ModelTurnInput`、`ModelTurnOutput` 保留现有调用形态、工具调用、文本流、完成原因与用量。现有 Chat Completions 为默认。Bailian Responses 按显式配置和已知模型能力分派。原生工具证据沿模型轮次返回，原生与应用工具重名时拒绝。 |
| Assistant 工具分派 | Agent 按租户、身份和原咨询获取当前获权项目、阶段和房间快照。持续跟进沿 `start_delegation`，核对原话、业主、房间及当前项目版本。工具回执绑定原运行和操作键。整条原话仅触发一次获权委托时，Agent 可用已持久化的登记回执结束本轮。供应商接受状态未知时保留 `indeterminate` 和待对账预约。 |
| KnowledgeRetriever / Evidence | 企业或项目知识按当前受众、项目成员、版本与来源状态检索。托管库是检索适配器，应用保存授权快照与来源定位。引用打开、历史投影和委托复核重新检查权限与原件。 |
| Construction | 项目、授权成员、有效计划、报告原始记录、精确版本方案、整改与复核由同一 Construction 服务及其事件投影维护。客户决定方案版本，工人提交获权现场原件，项目管理者核实并授权回传。四端依原角色读取获权视图。日周报读取相应周期的同源记录，每企业每周只领取一个调度槽并生成四个角色投递。 |
| Native Workflow / Durable Task | 已启用企业的委托事件统一走 PostgreSQL。消费者先提交 `delegation.delivery` 的租约，再由事务持有同一 token 复核并写回。企业、任务类型与 Outbox 事件 ID 决定执行键。租约到期可接管，已完成的执行回执可吸收重复投递。外部工具的未知副作用沿原探查与人工处理。 |
| Delegation / Outbox | `native_workflow_delegations` 是委托主记录，保留 `state` 和复核等待对象等兼容字段。房间水电和单事项复核共用 `native.delegation.v1`、企业串行顺序、租约和审计。每个事件可影响多条委托，各自按委托 ID 与事件 ID 记录。委托进展、原会话消息、事件处理结果与执行完成在同一事务写入。 |
| Conversation / Message | 原私有咨询保留消息序号、来源和身份。公开上下文绑定具体公开版本，公私切换时按当前来源与项目权限重建模型上下文。相同原话重放及同范围的进行中复核按原咨询去重。获权业务结果通过稳定的 Outbox 键回传原会话，读取和重试校验当前参与人、来源与业务版本。委托状态回执从原指令与本咨询当前获权委托重投影，方案和关闭回执从对应 Construction 事件重投影。 |
| Mini Program | C01 复用现有会话、引用及受保护原件入口。顺序增量与完整重进使用同一获权消息投影，窗口会重新核查未伴随新消息的来源撤回。Markdown 的节点从原助手文本派生，图片、引用、方案与回执保留各自受保护的业务入口。 |

公开网页候选的标题、域名和来源类别仅供选择。原生 Responses 提取回执的摘要按其来源地址绑定，不能自动进入可引用目录。C01 完整历史、引用打开和 LangGraph 祖先来源复用先鉴权，再从原读页通道核对正文指纹。页面变化、删除或暂不可读使用现有来源失效反馈。轮询增量沿已存快照投影，完整刷新重新检查公网原文。公开来源只说明对应文件的内容及已核实的适用时间。企业标准、获权现场记录和正式业务结果各自有独立来源。现行规范完整性仍为 Limited，见[集成验收](xiaok-integration-audit.md#i6-真实模型与获权知识验收limited)。

托管混合检索在授权后预检专用配置。缺配置返回 `retrieval_unavailable` 并记录原因；关闭知识、未命中和未配置各自保留状态。现有委托工艺核对使用同一检索与版本约束，核对回执按当前知识 epoch 及项目上下文失效，由后续获权事件重新读取。工艺引用和业务完成回执各自保留，施工结论由 Construction 服务写入。

公开 PDF 沿原 `read_web` 及 `web_fetch` 运行。后者只接受用户原话、已发现候选或已成功读到的网页附件链接。默认整件 4 MiB。超过整件上限的 HTTPS PDF 只在已知总长不超过 8 MiB、有强 ETag、服务端支持字节范围时读取，最多四段，每段至多 2 MiB，共用下载时限和原重定向、DNS 固定、TLS 边界。解析沿独立 pypdf 子进程。私有运行检查点保存原件、原始与最终 URL、原件 SHA-256、逐页状态及错误。页定位进入现有 Evidence，引用文字从同页原文解析，重进复核原件及页正文。上下文超限时只选完整相关页。扫描图或仅有重复水印时返回 `pdf_ocr_required`。企业 DOCX/PDF 的上传、解析及审核继续走原知识服务。

新准入的本人房屋文字咨询，在未索取档案时也能通过原 `query_business` 查询唯一在施工项目。服务端从会话绑定房屋，只开放施工域。无房间时返回实际节点和团队进度说明；指定房间时按当前项目精确房间核对，只补已向该业主发布的记录。无唯一项目、无唯一房间或无记录时说明本次查询范围。重进沿原业务快照复验，工地权限或记录版本失效时隐藏派生旧答。档案、正式图纸、到场联系及现场决策继续各走既有入口。公开围观不开放此读取。企业 RAG 省略 `scope` 时仍按原受众查询有效的企业通用和当前项目资料。

### 数据迁移与回退

使用 PostgreSQL 17。新库先由库 owner 预置 pgvector。通过 `cd admin` 后的 `npm run db:migrate` 应用迁移。入口在同一事务内锁定迁移、核对每条账本的时间戳与已知 hash、检查委托表形态和强制 RLS，再执行待应用 SQL。未知 hash、混合分支、重复时间戳、缺失前序和委托表与账本不符均停止升级。

空库和原 Native 路径依次执行 `0124 → 0125 → 0126 → 0127`。完整 Bailian 原路径执行 `0124 → 0125 → 0127`，由 `0127` 合流原表，允许同一来源消息下不同操作键的委托。已有 `0126` 的库仅执行 `0127`。水电委托按来源消息唯一，复核委托继续按企业、业主、操作键唯一。原账本行和原 SQL 保持原样，账本只记录实际执行的迁移。Bailian 原托管检索库的文本型 embedding 保留，切换到本地向量检索需要先完成向量数据迁移。

升版前保存源账本与可恢复快照，隔离验证应用角色、租户、触发器与原业务数据。升版窗口内停用历史 Worker，使用已核对的集成版本连接升级库。业务回退先停用相关企业开关及集成 Worker，保留现有记录与副作用回执。需要回退数据库时将快照恢复到独立库，核对升级后的新增业务和未知回执，再决定切换。按 [集成审查](xiaok-integration-audit.md) 核对具体迁移和生产验收边界。
