### 1.1 与知识专项分开的开发职责

本专项是小K客服/Agent的唯一开发主线：拥有意图与任务、原话/需求/项目上下文、模型协议及预算、工具选择/真实回执、H/B/K模型目录、引用和回复校验、人工/事件接续、恢复与聊天端接入。`admin/src/lib/assistant/agent/*`归Agent领域；资料已正确返回但生成、引用、上下文或工具循环失败，由同一统一负责人按Agent专项修复。

知识库通过现有`KnowledgeRetriever`/`Evidence`及来源重验提供获权原文、身份/版本/hash、定位和适用性；本专项使用知识适配器，保留原身份/epoch/撤回边界，不修改解析、分块、排序、知识发布或知识后台UI。具体字段和遗留混合文件的过渡归属统一查[二期开发边界](./xiaok-assistant-phase-2.zh-CN.md#agent与知识库的开发边界)，不另建第二份接口权威。

AG-08负责回答语义、证据使用、引用、操作与记忆质量；知识专业条目/解析/召回/版本缺陷交知识专项。AG-01/02只管理客户对话/需求记忆，AG-03及业务适配实时查授权项目；这些材料不自动进入企业知识库。客户隐私、项目事实和企业知识继续是不同授权来源。

Agent单元/服务先用固定Evidence夹具验证，再用真实知识适配器做受影响的兼容回归；本期新增语义核心题仍按总路线图实模至少两次。联合回归由Agent侧薄入口统一接入，知识侧提供Provider/证据检查，不因同一故障反复要求两边同时改源码。公共合同/基础设施变化登记并由一个明确负责人接入；各自的既有进度与Limited状态不因分工自动升级。当前只落实计划归属，代码交叉按需渐进提取。

### 1.2 统一开发与自动化验收流程（2026-10-21）

**当前执行规则。** 由用户指定的一个活跃聊天统一持续推进两个计划的开发与自动化验收，1.1节仅划分同一负责人下的代码领域与职责。执行[仓库统一流程](../AGENTS.md#unified-agent-and-knowledge-development-and-automated-acceptance)，取代旧文档中的例行主区冻结、独立测试聊天和跨聊天资源交接要求。历史停止通知和测试记录仍对应各自版本，不作为当前协调门槛或新增通过证据。

- 一个有界功能完成后，由同一聊天执行相关单元/服务及知识与Agent受影响兼容回归、修复失败、完成必需的配置实模/Stable原生检查、更新双语文档并按既有授权本地提交，然后继续下一授权阶段，不再例行确认。内部检查点或跳过的检查不算用户阶段完成。
- 验收绑定实际固定提交或已记录的源码/测试/配置快照，保留前后hash以及分开的夹具、调用与结果。原失败稿、源码漂移批次、unknown和费用事实保持；不混版本、不重放未知运行，不把修复稿算作首稿成功。
- 默认由统一聊天在已授权环境内串行执行。只有明确安排独立/并行工作时，才使用固定版本及隔离工作树、测试数据库、端口、Worker、配置、媒体/夹具和输出；隔离测试核对自己的版本时，开发可继续下一版本。隔离未准备好就串行执行，不把建设CI/容器平台作为当前阶段门槛；此规则不宣称隔离环境或调度器已经实现。
- Stable DevTools原生验收由同一流程中的一个控制者串行运行，保留已验证项目/窗口纪律。既有锁与空闲队列守卫由程序获取并在清理时释放，资源忙时自动等待或续做离线工作；例行争用无需用户批准冻结或跨聊天交接，也不允许抢占其他任务进程。
- 保留真实写入、可见反馈、持久重进、租户/权限/来源撤回和失败恢复检查；未执行/失败与Limited状态如实登记，批准设计及生产授权边界保持。

## 3. 上下文与记忆的实施约束

1. **组装分层：** 固定规则和当前请求、相关完整近期回合、当前任务/有效需求、可重建过程摘要、按需检索的历史与实时业务证据分别有预算。当前请求、更正/否定、未决事项及必要条件优先；工具调用/结果成对保留。权威业务状态不从摘要推导。
2. **压缩时机：** 每次模型调用前估算完整请求，包含工具schema、媒体估算、输出预留和后续工具结果余量。批次配置固定`inputBudget`、`summaryTrigger`、`summaryTarget`及估算方法，满足`summaryTarget < summaryTrigger < inputBudget`；达到触发值先去重/检索裁减，再压缩较早完整回合至目标，超过硬限额不发送。数值按获准模型能力和本期夹具测定、写入二期契约；保守字节保护继续有效，不直接套用其他模型token上限。
3. **摘要可靠性：** 保存原消息范围/ID、会话修订、对象范围、来源版本/hash及授权依赖；只在来源和修订仍有效时原子替换。由授权原文重建，避免反复只压缩旧摘要；需求记忆和未决事项不得仅剩一段摘要。摘要不新增客户确认、批准或现场事实；资料撤回后摘要/索引同样失效。
4. **遗忘与失败恢复：** 按当前对象检索较早原话并回读来源；仍有歧义才最小澄清。压缩失败保留原历史和上个有效状态，按有界必要上下文降级；当前输入或必要证据单独超限时返回现有可恢复反馈，不静默截掉条件、不编造记忆、不无限重试。归档后的有效事实可重建，原保留期与审计规则不因归档放宽。
