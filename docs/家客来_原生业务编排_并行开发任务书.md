## 5. 最小流程合同

| 合同 | 内容 |
| --- | --- |
| 定义 | schemaVersion、definitionId、revision、entryNodeId、节点、边和输入 schema |
| 节点 | nodeId、type、typeVersion、capabilityRef、配置与输入映射；能力来自服务端白名单 |
| 引用 | 上游 nodeId/outputPath；发布前检查存在性、依赖关系与兼容类型 |
| 发布 | 草稿可改；发布版本不可变；内容摘要及节点版本固定；旧运行继续绑定原版本 |
| 执行状态 | 当前节点、已处理事件、结果、错误与终态；首版有界 DAG，不支持循环与任意脚本 |
| 模拟轨迹 | mode=simulation、事件、节点状态、拟调用、fixture 结果、错误；无真实发送/保存回执 |
| 真实运行 | 宿主提供可信企业/用户/项目、租约和权限上下文；图定义不能覆盖这些身份 |

B 可拟新增 validateDefinition、compileDefinition、advance、simulate；这些名称不是仓库现有 API。advance 只返回新状态和待执行操作描述，simulate 只用 fixture 注入结果。导入流程 JSON 不允许任意 HTTP、SQL、代码、密钥、文件路径或可执行表达式。
时间、事件 ID 和生成结果由模拟输入显式给定；不在模拟器内建立真实调度。

## 6. 首版六类受控节点

| 节点 | 范围 |
| --- | --- |
| 触发 | 已有实际阶段事件或日报/周报计划；B2 用 fixture，B4 后绑定原入口 |
| 读取资料 | 按能力引用读取项目阶段、本期记录、获权照片、有效企业工艺；真实运行沿既有权限与来源规则 |
| 条件判断 | 知识开关、资料存在性、阶段/订阅是否符合；受限字段比较，不执行 JS |
| 内容整理 | 确定性模板或按需模型整理；保留既有零模型分支；不另建对话 Agent |
| 保存结果 | 调用现有阶段提醒/报告业务服务，返回真实持久化回执 |
| 站内投递 | 调用现有接收范围与 outbox 服务；不得直接发送外部微信、短信或邮件 |

真实运行前后均检查当前来源/成员/接收权限；流程发布权不等于数据访问权。模型不能宣布工程验收通过或替业务服务证明保存/投递成功。
首版不做任意脚本/HTTP/SQL节点、无限循环、子流程、多 Agent、付款审批、自动验收或新的长期记忆/知识库平台。

## 7. 两个模板

### 模板一：实际阶段变化后的提醒

实际阶段事件 → 读取当前获权项目/资料 → 判断订阅与知识状态 → 确定性内容或按需整理 → 保存原类型提醒 → 原站内投递。
同一事件重复消费只产生一次业务结果；未知阶段不猜测；知识关闭时保留当前确定性行为；进入阶段不等于完工或验收。

### 模板二：日／周报

已有计划 → 读取本期原始施工记录和获权照片 → 判断资料及接收范围 → 整理 → 保存原类型报告 → 原站内投递。
日/周共用 period 参数；周报使用本期原始记录，不把模型生成的日报当事实。保留四角色过滤、缺项表达、已阅/历史/重进和撤回行为。
B2 使用结构化合成样本与固定生成结果，不复制真实客户数据，不把旧《精艺》全册或报价范围引入一期知识。

## 8. B2 验收

- 两模板正常分支得到预期模拟轨迹，阶段提醒保留无需模型的分支。
- 重复事件不重复产生拟执行操作；同一版本/输入/事件序列结果一致。
- 缺失输出、错误引用、重复节点、非法边、未知节点、类型不符、循环或超出有界规模时明确拒绝。
- 读取拒绝、资料撤回、生成失败、保存失败、投递失败可由 fixture 分别注入，不统一显示“成功”。
- 模拟界面/输出有 simulation 标记；“拟投递”“模拟保存”与真实回执分开。
- 模块导入不启动任务、不读取生产密钥；模拟路径不具备真实模型/DB/网络执行依赖。
- 只运行明确的无数据库测试文件。当前 test:assistant 包含数据库测试，不能直接作为 B 的默认验证命令。
- 检查 git diff 的路径归属，A 文件、锁文件、现有路由和数据库迁移无变化。未执行和未通过的检查据实记录。

## 9. 环境隔离

B0～B2 不需要数据库或完整应用，不启动现成 assistant-worker，也不调用 /api/internal/assistant/jobs/run。
进入 B3/B4 后，独立 worktree 之外还必须隔离数据库及凭据、迁移连接、端口、Worker endpoint/secret、health 文件、配置、媒体/fixture、构建输出和调用记录。
现有 claimJob 在同一数据库全局扫描 chat_turn；换企业 ID 不能阻止另一分支 Worker 领取任务。jobs/run 还会推进知识批次、报告、站内投递及作品文案。
读取工具也可能写 step、链接和计量，知识检索还可能调用 Embedding；不能仅凭“query/search”名称把它当无副作用。
不共享 node_modules、.next 或输出目录。Admin 使用 npm/package-lock；不搬入 FastGPT 的 pnpm workspace/catalog，不顺手升级 React/Next/模型依赖。
公共 CPU/内存/供应商限流仍可能互相影响。B 初期零真实模型调用；首次联调限制为单 Worker 和固定样例，不同时压测，不抢 A 的 DevTools 或模型测试资源。
独立数据库没准备好时继续纯模块、fixture、设计和静态检查；不通过连接 A 的开发库来赶进度。

## 10. 提前联调与正式集成

1. A 出现稳定最小接口提交后，B 可在临时集成分支固定 A/B 两个 SHA，做能力结果映射验证；无需等 A 的后续 P2/P3 或全部 V1。
2. 提前联调优先用真正无外部副作用的读能力；没有这样的端口则用替身，或只在 B 的独立库执行完整现有生命周期。不得伪造 Lease 绕过队列/授权。
3. 模型接口沿 A 最终产物或既有稳定原生接口，以薄适配连接；B 不再写第二个供应商客户端、计量系统、重试器或问答循环。
4. 正式合入执行入口前，固定 A 的通过版本，重新检查 B 与该版本的兼容性。原两组四问的题目与标准不变。
5. 现有可复用基础包括 AgentRuntimePorts、runRenovationAgent、executePostgresText 及 Lease/runContext 等；它们并非现成通用工作流 API。
6. 当前队列只 claim chat_turn，装配器按固定 purpose 分派。新增流程入口/用途、版本关联及恢复机制由集成负责人设计，不能假设已有 enqueueWorkflow 或直接插任意任务。
7. 定义/版本表可新增，运行状态尽量关联现有 run/step；避免第二份助手消息、业务事实、计费台账或可争抢的队列。
8. 加法迁移只先在 B 库运行；合入时串行核对 schema、迁移编号/journal 和应用顺序，不直接拼接生成文件。
9. 真执行新入口默认关闭，检查在服务端创建任务/定时触发处生效；仅隐藏菜单不算关闭。A 普通问答可完全不加载 B。
10. 一个事件/计划周期只选一个有效执行路径；切换入口时处理在途旧任务，防止旧、新调度重复生成。业务去重沿原事件/报告周期键，不因发布新流程版本重新发送。
11. 重试依据既有真实回执与幂等。模型已派发、结果未知时保留 indeterminate/reconciling，不自动换引擎或重发。
12. 执行实例固定流程/节点版本，每次真实读取、动作和恢复仍复核当前权限与来源撤回；版本固定不代表权限永久有效。
13. 追踪实际模型调用链，并在 FastGPT 不可达时验证两模板；不能仅凭适配器名称或开关认定已去依赖。
