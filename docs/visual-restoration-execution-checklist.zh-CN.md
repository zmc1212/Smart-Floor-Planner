# 视觉还原执行清单

## 当前策略

HTML-first 对照原型、像素差异热力图和相似度评分暂时不再是强制门禁。只有用户明确要求，或它们能直接帮助定位具体视觉问题时，才作为可选工具使用；它们不会阻塞生产 UI 实施，也不会产生第二次实施授权。

本清单仍适用于设计图到代码的还原和针对已批准画面的重大视觉修正。保持现有 UI 的纯行为变更不需要执行本清单。

## 必须完成的还原核对

- [ ] 修改前确认一个已批准设计源、目标路由/界面、目标视口和相关宿主 UI。
- [ ] 检查当前已还原界面、已有视觉验收证据以及对应模块/设计文档。
- [ ] 设计源缺失、歧义或与另一已批准来源冲突时，暂停并请用户确认权威来源。
- [ ] 将每个关键插画、图标、纹理和艺术素材映射到提供的独立素材或已批准生产素材。
- [ ] 禁止把参考截图、复合设计图或浏览器截图切片、拼贴、重绘后作为产品素材使用。
- [ ] 行为/API 工作未获视觉变更授权时，保持现有结构、样式、素材和视觉层级。
- [ ] 实施后在适用视口验证生产路由。小程序页面遵守现有微信开发者工具路由和宿主窗口截图纪律；原生 Canvas 无法截取时补充真机验证。
- [ ] 更新中英文设计还原台账，记录最新设计源、视觉验收状态/证据和生产还原状态。

## 可选视觉排查

用户要求或确有必要定位视觉问题时，可在
`design-references/html-prototypes/<surface>/` 创建独立 HTML 原型、浏览器截图、叠图、热力图、区域评分和证据台账。结束后只保留当前有用的一套证据，删除旧截图、失败候选、重复下载、临时切图和解释器缓存。

可选对比证据只能辅助实施，不能替代已批准设计源、路由级视觉验证或用户明确的实施授权。
