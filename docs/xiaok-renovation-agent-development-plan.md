## 1. 第一版交付什么

家客来 1.0 = 十阶段轻量 Agent + 主动装修提醒 + 阶段知识问答 + 四端角色化周报。防水、水电专业 Agent 保留为高阶能力，不作为第一版每个阶段的前置。

| 功能 | 用户获得什么 |
| --- | --- |
| 十阶段轻量 Agent | 十阶段统一注册、知识包、提醒策略和周报模板；共享一个运行时。 |
| 阶段知识问答 | 普通问题按阶段知识包回答，企业知识缺失时明确未核实；深入专业问题转交现有专业 Agent。 |
| 主动装修提醒 | 真实阶段、计划、待办、问题与记录触发；去重、暂停、取消、恢复、撤权停止；优先站内。 |
| 四端角色周报 | 业主/设计师/老板/施工人员各自章节，来自同一 Construction 事实，保留来源、快照和版本。 |
| 统一红黄绿 | 提前绿、正常黄、落后红、待核实灰；施工/问题状态分开。 |

设备托管/收费、CAD/OCR、自动验收、完整 RAG、摄像头、采购库存结算、复杂报价与全节点自动审批不在第一版；报告照片不作为工程达标判断。预算、金额与报价由线下沟通确认。

## 3. 复用哪些成果

- 只用当前Agent/LangGraph、KnowledgeRetriever/Evidence、原权限、持久任务、幂等和计量。Evidence正确而回答错误归Agent；Evidence错误才修知识。
- 最小底座：一个对话Agent负责理解与表达，服务端负责权限/事实/动作；阶段提醒与日周报沿确定性工作流。普通问题不强制生成问项计划；任务规则按需装配，引用复核沿现有管线，不另造Agent或事实库。
- 企业知识开启后，标准取有效知识；关闭时仅给明确的通用建议，不确认企业规定。项目事实取获权业务记录。一般解释、企业规定、现场事实和未知明确区分；现场协作沿已批准团队核实话术，不替团队确认完成、批准或排期。
- 一般装修常识可有条件解释；需核实时效事实或用户要求联网时，实际搜索并核读公开来源，不凭空声称已搜索。企业标准优先用有效企业知识；混合问题标明依据，不把网页意见当企业规定。搜索不外传客户/项目隐私。
- 自由咨询与固定私人跟进会话并存。日/周报复用同一调度、生成、保存、投递和阅读机制，仅按周期选取对应时间段的原施工记录、实际阶段与照片；周报不拼接模型日报当事实来源。同一报告跨入口复用，无记录明确说明缺项，不编造进展或以空报告替代正常场景验收。
- 照片与文字共同供AI整理，保留原记录时间、项目及媒体出处；按角色过滤，业主只收到获准对客的内容。照片可辅助描述可见进展，不能单凭照片推断精确量数、隐蔽工程合格、批准或验收完成；撤回媒体时相关访问与派生内容沿原规则失效。
- 四角色按企业、本人项目、有效成员及来源受众取数。老板可看获权多项目，员工按项目分组；公开工地不公开私聊、内部记录或未批准机位。
- 报告/会话生命周期、批准设计及框架决定见[冻结规格§3](archive/xiaok-renovation-agent-development-plan-before-simplification-20261105.md)，只复用必要部分；直播与风格推荐沿用现有公开工地、作品和标签，不另建平台。
- 当前行为查[后台清单](admin-system-modules.zh-CN.md)、[小程序清单](miniprogram-system-modules.zh-CN.md)、[二期合同](xiaok-assistant-phase-2.zh-CN.md)；界面沿[还原台账](miniprogram-design-restoration-ledger.zh-CN.md)，不另建设计权威。

## 6. 验收与失败处理

### 6.1 开发与复测

1. 开始前明确用户动作、缺口和完成检查；先修已证缺口，再做定向单元/客户端、真实服务及必要Stable验证。未变证据复用，不先重跑全产品。
2. 工程、对话质量、真实客户端分层验证；记录首稿、修复、误拒、事实错误和费用，给校验器保留应接受/应拒绝样本。自然旅程保留不完整信息、渐进澄清、更正、追问和实际失败。预期与安全断言写在测试中，不教用户指定工具或答案。结构合法、引用存在、替身通过均不证明回答正确。
3. 工程错误、模型首稿、唯一修复、传输/环境失败、unknown与未执行分别记录。新实质语义核心在获准范围事前固定两次配置模型试验；不采到两次通过为止。
4. 同一业务期望连续两轮修复仍失败，先停止同类修词/正则/封套/采样。复用原trace提出共同原因和能区分原因的检查；有证据的新机制或独立工作继续，失败次数跨聊天保留。
5. 每次复测先说明行为变化或待排除风险，派发前后绑定实际源码、驱动和配置。批内漂移/首个阻塞失败/unknown停止该批，不缩绑定改绿、不重放未知调用、不把不可用费用记零。
6. 每个故障只阻塞实际依赖它的路径；先修可证明的根因并回到用户入口，不因局部失败无限扩测、重开全套或重写框架。无关历史缺陷和退出首版的功能不得成为新的推进门槛。

### 6.2 开发调用授权与历史停止批

**用户2026-11-05最新指示：后续按本开发计划持续开发，费用不设上限。** 本计划范围内必要的开发、模型/图片/Embedding调用和自动验收已有持续授权，不再逐批询问。继续如实记录实际用量、费用、预占和未知结果，不把未知费用记零。

原北京百炼`qwen3.8-flash`批在2202失败后停止，后10轮及3753unknown不自动重放。新机制按事前固定的必要范围测试，保留原首稿/唯一修复与失败次数；首个阻塞失败、unknown或批内漂移即停该批，按§6.1归因后推进可独立工作。无费用上限不改变五项V1范围、设计批准、真实客户/外部消息及生产部署边界，也不自动重建知识、重跑官网或开展模型横评。原授权原文仅作历史证据，见[冻结记录§6.2](archive/xiaok-renovation-agent-development-plan-before-simplification-20261105.md)。

### 6.3 防止方法偏离

- 用户最新方法约束高于交接的具体排查步骤：先证明必要检索后能准确自然回答，不把一个普通追问继续拆成调度、规则和内部测试任务。
- 修改前写清本轮具体问句、实际错误与预期回答差异；区分权限/来源/业务事实边界和理解表达问题。后者不默认转成提示词、正则、额度或新校验层。
- 必要快速检查可以先做；固定少量真实对话验证机制后，再完成受影响回归。未变证据复用，不为换聊天、文档或内部版本重开矩阵。两轮同类修复失败就停止该循环，不改名清零。
- 计划检查只检查这些约束未被遗漏，不证明执行遵守或回答达标。当前候选、失败与未验部分必须如实保留。
